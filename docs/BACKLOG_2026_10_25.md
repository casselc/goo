## G1 — Routine verification and reproducibility

**Baseline problem (before `374bbd5`):** the default [API workflow](../.github/workflows/api-contract.yml)
regenerates schemas and runs selected wire/saved/proxy checks, but does not run
all root Go or Node tests. Its selected wire pattern omits trace-search handler
tests even though schema fixtures include that route. Rich local evidence is not
a substitute for a repeatable default gate.

**Delivered fast slice:** `374bbd5` adds root Go/all Node CI and the trace-search
wire selection. Local commands and deliberate failing controls pass; a hosted CI
run and nested-module reproducibility are not claimed. See [validation](../VALIDATION.md).

**First bounded cut:** retain the API job; add full root Go and all Node test
coverage with pinned supported toolchains and existing dependency locks. Include
the new route's actual handler tests, not schema-only fixtures. Keep the existing
Python API/proxy/docs checks. Inventory other Python/instrumentation checks before
adding heavy requirements to the fast tier.

**Acceptance:** clean-checkout commands; a deliberate failing Go/Node/trace-route
control causes the appropriate job to fail; opt-in source tests report skipped
without their environments; generated API files do not drift. Document actual
run coverage and tool/dependency versions. CI must not silently pass because a
sibling module or optional tool is absent.

**Following enabling slice, separately reviewed:** reproducible nested
verification/instrumentation modules and pinned sibling quint-go/hegel/tool
requirements, then one thin clean-lab/restart journey. Use ordinary OTel data and
reuse the existing source/custody failure checks. Keep the optional XTDB tier
separate from the default ClickHouse/UI loop. No requirement to run all historic
journeys on every commit, and no numerical property/negative-control quota.

## C1 — Generic-source startup profile

**Problem/evidence:** [Go startup](../cmd/goo/serve_http.go) requires binding,
inventory and instrumentation scope/version before generic routes are registered,
and defaults to `config/operations/checkout.yaml`. [Python](../server.py) imports
[grammar](../grammar.py), which eagerly loads `definitions/reservations.json`.
This is a confirmed adoption dependency, not a claim the lab is broken.

**Deliverable:** one explicit generic-source profile using the existing Go server
and browser static/proxy process. Generic record/native discovery, exploration,
Services and supported saved work start without demo bindings or manifests.
Declared-operation/prepared-fact/example capabilities are optional and clearly
identified as unconfigured. Keep the current lab profile and its validation.

**Boundary decisions before code:** define route/capability behavior for an absent
optional family; do not invent a healthy empty operation inventory or swallow an
invalid package explicitly configured by the user. Keep ClickHouse/store options
explicit. Do not remove Python, rewrite the CLI or introduce a new global schema.

**Acceptance:** start from a directory lacking all sample/binding/inventory files;
serve UI/spec/proxy and execute an ordinary non-Go OTel Activity → service → fixed
question journey. Optional-family absence remains distinct from no telemetry and
source failure. Existing demo/operation route fixtures and explicit-package startup
failures remain correct. Opening/configuring the UI does not run an expensive
population query merely to discover startup capabilities.

## C2 — Automatic operational dashboard families

**Problem/evidence:** [dashboard planning](../exploration/dashboard.go) correctly
labels mixed-kind spans as records. [Existing native capabilities](../measurements/instrument_capabilities.go)
already recognize supported HTTP/messaging instruments. Adding another generic
RED widget would obscure the denominator rather than resolve it.

**Initiative:** make discovered web/RPC, database, messaging, host/runtime and
Kubernetes entities immediately useful through capability-driven default
dashboards. Use RED, USE and role-specific views where their signals support
them. See [the family matrix and staged acceptance](AUTOMATIC_DASHBOARDS.md).
Manifests enrich defaults; they are not required. Missing signals should leave
useful supported panels visible with compact actionable capability details.

**First vertical slice (C2a):** keep All spans and add one named HTTP server-span observation
lens through the existing planner. Declare supported span-kind/key/version rules;
show operation/route, recorded error/status and duration at that population.
A selected lens is one active intent, not simultaneous queries for every profile.
Reuse relevant eligible HTTP native instruments and existing native presenters,
with their own stream identity, units, interval coverage and read basis.

**Semantic limits:** call span-derived values observed span records/rates and
recorded outcomes. Do not infer unique requests, roots, traffic completeness,
business success or a native/span/log common denominator. Discovery eligibility
is not conformance or interval-coverage verification. HTTP native v1.30 and prepared
HTTP v1.37 profiles are different contracts; no silent alias union or version
upgrade. Prepared request deduplication requires its reviewed binding and is not
implicitly applied to arbitrary raw spans.

**Acceptance:** mixed server/client/internal/retry spans; HTTP keys only on client
spans; missing versus empty route/key; non-HTTP fallback; same service name in
separate namespaces; ordinary manifest-free OTel; unavailable or incompatible
native instruments; zero versus unobserved signals. Validate exact selectors and
full counts, source-free planning/staging, explicit execution, independent native
bases, bounded source effects and parent return. A real task follows service lens
→ operation population → trace search/waterfall. Refresh whole-screen and nested
mobile frames, not only a cropped summary.

**Observed usability follow-up:** journey 187 whole-product frames expose
persistent service-catalog controls and repeated scope/context chrome above an
opened entity, especially on mobile. The HTTP panel is compact, but this broader
entry overhead is not resolved by its timeline polish. Consolidate the selected-
entity header and disclose catalog controls while retaining exact scope, Back,
focus restoration and source-free local navigation; verify the whole viewport.
Treat this as a bounded shared entry refinement for subsequent families.

**C2a follow-on:** after HTTP (C2a.1), deliver an explicit incoming RPC profile
(C2a.2) with method/status/duration defaults; do not leave RPC as a catalog-only
promise or blend its denominator with HTTP.

**Remaining initiative stages:** C2b adds role-specific messaging and database
client/dependency dashboards; C2c supplies pool/runtime/host USE panels with the
actual typed metric/resource prerequisites; C2d supplies Kubernetes entity
discovery and operational dashboards for cluster/namespace/workload/pod/container/
node scopes. These are first-class planned deliveries, not a promise that the
current service inventory or catalog already executes them. RPC and additional
roles use explicit supported profiles.

**Prerequisite contracts:** native finite fractional gauges already work. Add
nonmonotonic sum/UpDownCounter or fractional-counter semantics only where needed
by an actual panel, with source parity. Host/Kubernetes streams need an explicit
resource identity/discovery contract; do not synthesize service names/instances
or globally relax existing validation. Capacity ratios require matching identity,
time and units. Client spans alone cannot supply DB server, broker or cluster
health. Reuse supported kernels and field hints; no universal request abstraction
or dashboard editor is required.

## C3 — Native interval to record context

**User task:** an engineer sees an interesting gauge observation/counter interval/
histogram interval and wants to inspect nearby logs or spans without rebuilding
its service/window scope by hand.

**Deliverable:** from one existing native inspector, stage an existing fixed
record question with defensible shared environment/resource/time facts. Run
explicitly performs the fresh record read; Back restores the retained native
context without polling or rerunning. Adopt the same compact scope/actions and
record/trace owners already used elsewhere. Add no new global destination.

**Required mapping contract:** preserve service namespace missing/empty/value
states and source provenance. Transfer instance or other resource predicates only
when the shared identity/mapping is established; an explicitly broader service
context must say it is broader. Native metric name, instrumentation scope/version,
schema URL and metric-only dimensions are not automatically span/log filters.
A common time interval is contextual evidence, not a join or causal relationship.

Define nanosecond-to-record-window behavior before implementation. Preserve exact
interval boundaries with supported predicates or disclose an intentional envelope;
do not silently round away boundary observations. Unsupported, invalid or too-wide
intervals must not become an arbitrary current-time query. A deliberate broader
window is a separate staged intent.

**Acceptance:** actual gauge/counter/histogram cases supported by the chosen first
adapter; instance/namespace distinctions; sub-millisecond edges; reset/gap/unknown
coverage; no matching records; canceled/late reads; unchanged parent identity and
focus. Staging/disclosure/Back add no telemetry reads. A source-backed journey
follows one interval → scoped records → trace, then returns. The first slice may
support one interval family if the other families' mapping is not yet defined.

## C4 — Lean record aggregate projection

**Prerequisite:** measure issued reads, SQL size and representative small/larger
cardinalities for selected callers. The source has finite budgets but a bounded
list is not a scan-cost bound. Do not claim a performance improvement from source
inspection alone.

**First deliverable:** a narrow typed aggregate execution path adopted by exactly
two callers: counted field values and the new service lens, or counted values
first if that is the clearer seam. Reuse validation, predicates, source adapters
and count/group/series compilation. Do not fetch irrelevant record pages or
field inventories, and do not fake an inspection result with empty rows.

Preserve the existing `/explore` wire/capture contracts. Define which aggregates
are read and whether they share one source statement; independently read values
retain separate provenance and changed-between-reads behavior. Any shared owner
helper must emerge from matching real lifecycle contracts in those two adapters.
No universal result object, auto-retry or native/prepared-kernel merger.

**Acceptance:** actual read-set conservation, exact totals/groups and missing/empty
states, numeric predicate retention, bounded failure/cancellation, source/reference
parity and old capture IDs/bytes. Measure before/after under the same declared
fixture/settings. Current >1,000-group refusal remains intact. A useful high-
cardinality summary is a later separately typed operator, not silent truncation.

## C5 — Conditional trace-search definition reuse

**Activation condition:** select a concrete recurring multi-condition question
and its entry/reopen task. Do not schedule persistence merely because trace
search is the most recently added feature.

**Deliverable:** one versioned typed definition containing title, exact conditions,
bindings and window intent through existing immutable/library mechanics and a
family-specific adapter. Reopening stages intent without reading source telemetry;
Run is fresh evidence. Fixed bounds stay fixed unless the user explicitly chooses
a separately modeled fresh-window action.

**Acceptance:** canonical condition/window/binding round trip, revision/title
collisions, old store/ID compatibility, source unavailable on reopen, canceled
or obsolete execution and dirty-intent recovery. Saving a definition stores no
observed counts or representative witnesses. A trace search must not be flattened
into single-span `Query.where` merely to fit an existing saved-question schema.

**Excluded:** exact search-result promotion, persisted paired trace comparisons,
new evidence stores or bigger shared token pools. Search may return 8 MiB while
the existing observation bank accepts 2 MiB per entry. Exact result custody needs
an explicit server-held typed budget/idempotency/lifetime design and consumer.
Existing stored raw pages should be reused for read-only visualization first.

## Cross-cutting stopping rules

- No source read from opening an editor, changing display, restoring a draft,
  staging context or selecting a held comparison. Explicit reads retain their
  actual fixed scope, source clock and result grain.
- No page/sample presented as a population, missing telemetry as health, duplicate
  IDs as unique invocations, or metadata eligibility as verified conformance.
- New source routes require an effect/admission/cancellation review. Streaming,
  ordinary reads, source-bearing publications and pure operations keep separate
  lifetimes. Policy changes use deliberate route fixtures; no incidental quota
  or timeout changes hidden in a UI feature.
- Refuse oversize/unsupported evidence honestly. Do not raise budgets, accept
  client-provided observed statistics, silently reread an observed result for Save,
  or change immutable identifiers to fit a common abstraction.
- Mechanical formatting, profiling and shared-helper extraction have their own
  reviewable purpose; they are not pretexts for a framework or store migration.
- Verification is proportional to changed semantics and race/custody risks. Use
  independent raw/source expectations and meaningful rejecting controls, update
  affected diagrams/storyboards/frames, and report skipped gates as skipped.
- Stop at a dependency/semantic contract when needed. No automatic expansion into
  high-cardinality, collector health, collaboration, training, warehouse or
  production deployment work.
