coverage with pinned supported toolchains and existing dependency locks. Include

control causes the appropriate job to fail; opt-in source tests report skipped

sibling module or optional tool is absent.

**Following enabling slice, separately reviewed:** reproducible nested
verification/instrumentation modules and pinned sibling quint-go/hegel/tool

reuse the existing source/custody failure checks. Keep the optional XTDB tier

## Cross-cutting stopping rules

- No source read from opening an editor, changing display, restoring a draft,
  staging context or selecting a held comparison. Explicit reads retain their
  actual fixed scope, source clock and result grain.
- No page/sample presented as a population, missing telemetry as health, duplicate
  IDs as unique invocations, or metadata eligibility as verified conformance.
- New source routes require an effect/admission/cancellation review. Streaming,
  ordinary reads, source-bearing publications and pure operations keep separate
  lifetimes. Policy changes use deliberate route fixtures; no incidental quota
  or timeout changes hidden in a UI feature.
- Refuse oversize/unsupported evidence honestly. Do not raise budgets, accept
  client-provided observed statistics, silently reread an observed result for Save,
  or change immutable identifiers to fit a common abstraction.
- Mechanical formatting, profiling and shared-helper extraction have their own
  reviewable purpose; they are not pretexts for a framework or store migration.
- Verification is proportional to changed semantics and race/custody risks. Use
  independent raw/source expectations and meaningful rejecting controls, update
  affected diagrams/storyboards/frames, and report skipped gates as skipped.
- Stop at a dependency/semantic contract when needed. No automatic expansion into
  high-cardinality, collector health, collaboration, training, warehouse or
  production deployment work.
