## P1 — Scan and act on mobile Activity

Use the existing record summary/table/action primitives to reduce repeated action
rows and toolbar separator fragments. Choose one obvious inspect affordance and
compact selection/trace access based on the current task; keep touch and keyboard
actions discoverable. Do not replace the stream with an upfront query builder or
add another global toolbar. Native display remains passive; selection/source state
belongs to Activity.

Acceptance: compare the same short/long ordinary OTel records before/after at
320/390/700px and desktop. Measure row/toolbar geometry and visible records; do not
claim improvement from screenshots with different content. Inspection and selection
must remain distinct, accessible, and stable across append/eviction/pause/resume.
Selecting or revealing actions performs no source read. Trace continuation retains
its scope and source ownership. Cover detached/stale actions and hidden-document
behavior; update the relevant Bombadil actions and real journey frames.

## P2 — Find saved captures by task and recency

First define a bounded metadata query contract over the existing immutable capture
catalog: literal title search, signal/kind and environment, with clearly named
captured-time ordering and deterministic ID tie-breaking. Confirm which receipt
fields reliably describe service scope before offering a service filter. Existing
ID reopen must continue to work. Reuse the shared catalog/table presentation.

This is the general immutable capture catalog, distinct from the already-delivered
optional retained-evidence catalog search. Do not rebuild that separate capability.

The current cursor is an ID position and must not silently change meaning. New
filter/order cursors must bind their query and reject incompatible reuse. Search
and ordering cover the whole admitted catalog, never just the current 20-item page.
If an index is needed, specify publication/rebuild/integrity and scan-limit behavior
before implementing it; retain the current immutable files and corruption refusal.
A page-local sort is not global recency, and file mtime is not capture time.

Acceptance: captures on later pages can be found; same titles remain distinct;
missing/literal-empty scope stays distinct; filtered pagination is deterministic
for an unchanged catalog; no matches, unavailable index, corrupt content and scan
limits have honest states. Catalog actions and reopen perform no telemetry reads.
Validate API/OpenAPI and storage/identity contracts plus one real save → navigate
away → find → reopen task. Do not mutate existing captured questions or evidence.

## P3 — Explain comparison support before ranking certainty

Show the existing side counts/denominators and coverage beside descriptive change,
then offer an optional minimum-support control where both sides are defined.
Specify whether the threshold applies to either/both sides, its treatment of zero
and unavailable support, and the exact ranking population before code. Keep this
separate from any statistical inference feature.

Acceptance: exact large counts, zero/no-data/unknown and missing/empty categories
remain honest. Thresholding changes presentation/ranking, not population totals or
stored evidence. Persist only supported view settings through the existing saved
view contract. Test low-support high-relative-change examples, unavailable sides,
keyboard use, immutable captures and late/withdrawn owners. No significance or
anomaly-confidence label without a separately justified statistical model.

## P4 — Reuse one recurring multi-condition trace question

Use the concrete task “find traces with a slow database observation and an error
observation, possibly in another service.” Preserve existing trace-search semantics:
conditions may share a witness, each requires an observation in the fixed enclosing
window, and only condition 1 receives original population filters.

Design a versioned question-definition extension using existing saved-question/
investigation surfaces and immutable revision rules. Reopening stages the definition
without a query; Run explicitly evaluates it. Confirm scope/condition/limit fields
before extending the API/protocol. Do not add a parallel store or promote limited
witness rows into a full-trace capture.

Acceptance: source-free save/reopen/share, exact predicate identity (including
literal namespace and numeric values), deterministic definition identity, old
record/native questions unchanged, and a real cross-service matching task. Required
model/property/negative controls must reject a missing condition, accidental AND
on one span, and unsupported topology/ordering assumptions. Add this only after
P2/P3 or a named recurring user task justifies reprioritization.
