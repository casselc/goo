## B1 — Direct Go delivered in 237; proxy follow-up

Go JSON decoding now has a 15-second receive deadline and context-cancellation
interrupt. Successful complete decoding clears it before source/response work;
errors expire it and close the connection to prevent implicit body-drain stalls.
All remaining inline transport decoders adopt this reader. Real socket regressions
cover partial JSON, an unclosed complete value, malformed prefix and a large
unknown-field error, with zero effects and subsequent admission while peers stay
open. This guarantee requires net/http ResponseController deadline support;
in-memory responders and wrappers that hide transport capabilities cannot supply it.

### B1p — retired by runtime consolidation 238

The Python server is removed in 238, so this proposed proxy repair is superseded.
Browser requests now use the bounded Go receive path directly. The following
observation records why the old boundary was removed, not remaining work.

An isolated real-socket Handler probe confirms partial uploads still block after
150ms with no forwarding, releasing on peer close. Define a finite receive timeout
and reject short/truncated bodies before forwarding. Restore the socket policy
before upstream response/SSE handling; cover valid maximum bodies and no hidden
forwarding. The direct Go change alone did not fix it; removing the proxy retires the issue.

### Original B1 acceptance — Bound incoming body receive independently of source execution

The architecture review reproduces actual admission held after explicit cancellation
while a peer leaves JSON incomplete; a synchronous Body.Close also blocks. Define
transport receive deadlines/cancellation separately from source deadlines. Start
with direct Go ingress; inspect/probe Python's blocking upload path separately.

Acceptance: real socket, one admission slot, partial JSON and a complete value with
an unclosed body; cancel/deadline releases capacity while the peer remains open,
no source call/publication starts, and the next valid request succeeds. Preserve
size/trailing-data refusal, tombstones, supported large bodies and SSE lifetimes.
Context expiry alone is not proof of interrupted socket I/O. Keep this cut finite.

## P2 — Delivered 242: find saved captures by task and recency

captured-time ordering and deterministic ID tie-breaking. Confirm which receipt

ID reopen must continue to work. Reuse the shared catalog/table presentation.

This is the general immutable capture catalog, distinct from the already-delivered
optional retained-evidence catalog search. Do not rebuild that separate capability.

Define a bounded metadata I/O/allocation budget. Current Load decodes/verifies up
to 24 MiB of complete capture content; do not extend that to 10,000 complete bodies
per search. Decide which integrity checks happen on list versus reopen/rebuild. A
metadata-only index cannot detect arbitrary later payload corruption without reads.

The current cursor is an ID position and must not silently change meaning. New
filter/order cursors must bind their query and reject incompatible reuse. Search
and ordering cover the whole admitted catalog, never just the current 20-item page.
If an index is needed, specify publication/rebuild/integrity and scan-limit behavior
before implementing it; retain the current immutable files and corruption refusal.
A page-local sort is not global recency, and file mtime is not capture time.

Acceptance: captures on later pages can be found; same titles remain distinct;
missing/literal-empty scope stays distinct; filtered pagination is deterministic
for an unchanged catalog; no matches, unavailable index, corrupt content and scan
limits have honest states. Catalog actions and reopen perform no telemetry reads.
Validate API/OpenAPI and storage/identity contracts plus one real save → navigate
away → find → reopen task. Do not mutate existing captured questions or evidence.

[The delivered metadata contract](CAPTURE_CATALOG_SEARCH.md) defines per-entry/
