## Review gate

Keep the complete Activity → isolate → supporting signals → save/reuse task as
the acceptance unit. Each bounded cut gets source/diff review, relevant checks,
docs/frames where affected, cleanup, commit and push. Revisit the whole product
after P1/P2, or earlier if actual use contradicts this order. Root fast gates stay
useful; property/model/browser campaigns should catch distinct failure classes,
not generate quotas or large evidence bundles for internal edits.

## Deferred until a named task or prerequisite

Do not automatically add generalized dashboards, a shared canvas, alert scheduling,
training exporters, RUM/profiling, arbitrary expressions, DataFusion/CEL/KCL,
mandatory XTDB/bitemporal storage or live Databricks execution. Preserve existing
offline translation and annotation capabilities. New OTel convention/resource
profiles need exact source/version/unit contracts and one real user task, rather
than another disconnected panel. Shared production deployment needs a selected
authentication, query isolation, retention and restore design first.
