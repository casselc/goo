through the backlog, reviewing the whole product, revising the roadmap and

### Accepted bounded integrity work

- **I1:** reject malformed prepared string literals before accepted filtering,
  grouping or subject identity; preserve valid Unicode/empty values and visibility
  rules. A reproduced direct-Go input defect, not generic hash cleanup.
- **I2:** resolve native package writer/catalog capacity consistency before further
  revision-producing features. Source-confirmed, not endpoint-reproduced; preserve
  duplicate retries, concurrent publication, existing IDs and over-limit files.

These can be separate small cuts and do not require holding Activity fixes or P2
metadata design behind all medium architectural recommendations.

### Product decisions alongside the fixes

Define the supported adoption path for OTel missing the optional environment
attribute, and whether keeping exact observed occurrences is baseline or an
optional capability. Communicate current prerequisites now. No silent environment
wildcard, mandatory XTDB, client-asserted source custody or relabeling a fresh
capture as the original selection. These decisions do not authorize a universal
selector/store redesign or block all capture-discovery work.

Small later enablers: source-policy conformance probe; snapshot promotion lock
isolation; compiled-plan metadata ownership; named plot keyboard/update policy;
explicit deployed-asset identity and a selected required browser tier. Duplicate
retention status and measured row-projection costs stay lower priority than scope,
inspection and saved-work discovery.

## Review gate

Keep the complete Activity → isolate → supporting signals → save/reuse task as
the acceptance unit. Each bounded cut gets source/diff review, relevant checks,
docs/frames where affected, cleanup, commit and push. Revisit the whole product
after Activity continuity and the first P2 slice, or earlier if actual use contradicts
this order. Include a full scope → signal switch → inspect → supporting context →
preserve → navigate away → find → reopen task, not entrance screenshots alone. Root fast gates stay
useful; property/model/browser campaigns should catch distinct failure classes,
not generate quotas or large evidence bundles for internal edits.

## Deferred until a named task or prerequisite

Do not automatically add generalized dashboards, a shared canvas, alert scheduling,
training exporters, RUM/profiling, arbitrary expressions, DataFusion/CEL/KCL,
mandatory XTDB/bitemporal storage or live Databricks execution. Preserve existing
offline translation and annotation capabilities. New OTel convention/resource
profiles need exact source/version/unit contracts and one real user task, rather
than another disconnected panel. Shared production deployment needs a selected
authentication, query isolation, retention and restore design first.
