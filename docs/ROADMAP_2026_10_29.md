## Bounded reliability and process enablers

- Per-ID or resumable metadata repair, independently of total payload volume.
- Keyed in-flight publication so one filesystem save does not hold the whole
  snapshot bank; preserve reserved custody and ambiguous-commit retry identity.
- Detached prepared compiler plan metadata using concrete internal ownership
  helpers; no advanced machinery required of users.
- Shared plot keyboard and keyed data-update policy before expanding live charts.
- Method-specific API effects, especially source-free capture GET.
- One selected required complete browser tier, with pointer/keyboard paths and
  terminal assertions. Keep broad native/model/Bombadil campaigns opt-in; preserve
  strict named verdicts and distinguish safety replay from task completion.
- Automated served/build identity preflight rather than manual byte comparison
  being the only deployment guard. Add a separate metadata I/O limiter only after
  a measured deployment/task justifies it.

Each cut gets source/diff review, a distinct relevant counterexample, real task/
frames where affected, cleanup, commit and push. Do not count broad test quotas or
large evidence bundles as progress. This review creates proposals, not shipped
fixes. Re-review the whole product after the correctness gate and the first
adoption/preservation task, or earlier if the task evidence changes the order.
