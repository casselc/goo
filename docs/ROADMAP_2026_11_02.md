# Product roadmap — 2026-11-02

> Historical execution order, superseded after 314 by the [November 3 roadmap](ROADMAP_2026_11_03.md).

This is the finite continuation after the [312 whole-product checkpoint](reviews/WHOLE_PRODUCT_PLAN_312.md).
It supersedes the execution order in the [October 30 roadmap](ROADMAP_2026_10_30.md)
and the historical [243 acceptance backlog](BACKLOG_2026_10_29.md). Those documents
remain delivery/research history, not parallel active queues. Proposed work below
is not a claim of implementation or production readiness.

The product remains: **see what is happening → isolate a population → follow its
supporting signals → preserve or reuse what was learned**. Ordinary OTel producers
need no Goo manifest or annotation to start. Code-managed and interactive views
share checked intent; observations retain their own scope, read basis and custody.
Keep one Go server and application-owned source execution, passive framework-neutral
components, qualified fields, honest unknown states and explicit stage/read/save
boundaries. Prerelease code can change directly; compatibility scaffolding is not
an outcome.

## Active order

### 312 — Correct unsafe or impossible transitions

**Delivered.** The review found small but material defects in otherwise delivered
flows. The bounded corrections below are implemented and validated; do not broaden
composition or add controls to conceal unresolved owner/context semantics.

| Correction | Acceptance |
| --- | --- |
| Shared selection-tray command lease | Apply, Open, Undo, Clear and comparisons check the same current owner, scope generation, draft/selection and readiness. Reattached stale controls cannot execute obsolete queries or edit a replacement selection. Pending page/record/source work and invalid drafts block conflicting commands. Preserve explicit Apply-read versus Open-stage semantics. |
| Facet comparison promotion | An eligible ordinary count+facet remainder offers **Include comparison without facet**, explaining that the control/template marker is removed while applied predicates stay. Validate one atomic source-free transition preserving selected/baseline questions, aggregate and record kind/fields. No silent control loss, facet/comparison coexistence redesign, or expansion of the unsupported span-status profile. |
| Facet lookup lifetime | Replacing/remounting a facet on repeated child/Back disposes and removes its previous lookup. Retained parent counts and controls remain usable without a read; live request/lookup ownership stays bounded across cycles. |
| Terminal record-page certainty | A short terminal page that cannot account for the independent count is diagnosed rather than reported as an observed complete end. Keep valid full pages, final pages, out-of-range offsets and no-data distinct. |
| Returned question ownership | Full/page results detach caller-owned predicates, groups and bindings; discovery/inventory results detach namespace pointers. Later caller mutation cannot change the declared question while the basis and SQL stay frozen. Reuse existing concrete ownership helpers. |

Use counterexample-focused Go/JS tests, real SDK/source browser paths and negative
controls. Keep actual retained-state and source-request assertions; a replayed safe
prefix is not a finished user task. Update affected storyboards/frames, review each
patch, clean temporary stores/campaigns, then commit/push. This is a correctness
bundle, not permission to create a command bus, universal resource manager or new
query planner.

### 313 — One active investigation surface

**Delivered within the ownership cut.** [313 validation](../VALIDATION.md) and
[actual journey/frames](journeys/313-active-canvas.md) cover retained state, explicit
reads, current titles/restrictions and request cancellation. Outer context-return
consolidation and remaining visual density are explicit follow-ups below. When a population is active, put its records,
charts and current scope first. Do not leave a dormant root question builder and
its Run controls above a different active owner. Give the user one obvious way
back to the retained parent and one clear next action. Preserve drafts, selection,
scroll/focus and explicit source effects; do not hide the only usable editor or
silently restart Activity. Retiring trace/log/context reads should cancel the
underlying request through the existing fetch adapter, not only ignore its late
answer; preserve the separate return/focus lease.

Reconcile titles with the current field context: default HTTP route titles can be
misleading after category rebinding. Keep authored text literal and show actual qualified grouping separately. An omitted
aggregate title derives from the current grouping/measure; the new shipped HTTP
aggregate opts into that default while keeping its catalog title. Reduce duplicate context/prose and
controls through the existing component library, not another navigation destination.
Disabled actions must identify the actual unsupported projection/capability, rather
than claim a missing breakdown when one is already applied; keep unsupported
span-status comparison semantics explicit.

Acceptance: one actual Activity → service/view → scope → trace → Preserve/reopen
journey at desktop and narrow width, practical keyboard exits/next focus, clear
current-versus-retained scope and no source reads on local return/presentation.
Source changes remain with the existing parent generation/executor. Extract a
small workspace adapter only where this real task needs an update/suspend/dispose
boundary; do not schedule a whole-module rewrite before the outcome.

A direct Activity-to-service handoff is a review candidate, not yet a promised
shortcut. Define which observed identity, environment policy, window and predicates
can be carried across signal/profile boundaries before adding it. The 312 task confirmed manual environment re-entry and a new
120-second discovery window; that is a visible detour, not retained Activity scope.
A log-body predicate must not silently become an HTTP-span predicate or disappear
under an "exact scope" label.

### 314 — Measure source demand, then remove unnecessary work

**Delivered:** [measured fixed-baseline reads](FIXED_BASELINE_READS.md) and
[314 journey](journeys/314-source-demand.md). The original bounded acceptance below
is retained as planning history. Browser budgets counted
HTTP actions, not all ClickHouse statements. Record actual request/SQL demand and
elapsed behavior for one service Customize → population → facet → cohort → trace
flow, including independent count/group/page/field/summary reads, cancellation and
retirement. The 312 service entry recorded eight source HTTP calls and two identical
discovery bodies; determine their owner/freshness purpose before removing either. Distinguish source-derived statement counts from measured latency.

Use an existing aggregate-only acquisition profile for a comparison operand only
when it can produce the same admitted query, counts/groups/measures, read receipts
and quality semantics. Do not forge a full snapshot from a partial DTO, strip a
requested measure, infer upstream completeness, parallelize everything or cache
across held/current/baseline identities. Compare correctness and actual demand
before/after; set one bounded regression budget for the changed task. If measurement
does not justify an optimization, keep the profile and close the experiment.

Actual 313 frames confirm a separate density problem: a two-value method facet
uses roughly 430px, and service/Activity/trail ancestry adds about 400px on a narrow
nested canvas. Root-editor ownership is corrected; this does not mean the data is
high enough in every viewport. Retain a finite shared-component cleanup candidate:
compact facet rows/actions, one readable context/read-facts disclosure and less
nested card chrome. Review contextual return consolidation with explicit ancestry
semantics, preserving keyboard/touch targets, paused parents and explicit reads.
Prioritize this at the post-314 review; it does not displace the source-demand task.

A separately retained rendering candidate is the facet: its 1,000-item cap is not
a total-byte or DOM-work bound. Measure the
legitimate long-value case, give property and attribute inputs one documented byte
budget, and avoid rebuilding unchanged rows for readiness-only updates where the
measurement warrants it. Budget refusal must not become silent category truncation
with an exhaustive-total claim. Local Find should announce its loaded-match count,
including zero, separately from the full applied-population denominator. These
changes are not prerequisites for the source-profile experiment; schedule them
from the active-surface or measured rendering evidence, not as an extra unbounded
314 performance programme.

Validation parity belongs in these changed boundaries: Go, browser and OpenAPI
must agree on applicable roles/profiles/defaults. Maintain real producer-to-consumer
fixtures and small shared validators. A new validation language or forced single
numeric table model is not an independent milestone.
