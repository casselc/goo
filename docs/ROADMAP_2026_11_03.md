# Product roadmap — 2026-11-03

This is the post-314 reconciliation of the [312 product review](reviews/WHOLE_PRODUCT_PLAN_312.md)
and [November 2 roadmap](ROADMAP_2026_11_02.md). It replaces their active execution
order; earlier reviews remain evidence and research, not additional backlogs.
Proposed work below is not a delivered capability.

The product stays **see what is happening → isolate a population → follow its
supporting signals → preserve or reuse the result**. Start with ordinary OTel
telemetry. Keep one Go application-owned executor, reusable passive web components
and a checked view grammar. Current observations, held observations and durable
questions have different ownership and certainty; compact presentation must not
blur those differences.

## Delivered and learned

- **312:** closed stale selection commands, impossible facet/comparison promotion,
  facet lookup lifetime, terminal-page certainty and returned-question aliasing.
  Explicit promotion removes the facet control while retaining applied predicates;
  it does not introduce general facet/comparison coexistence.
- **313:** active populations hide/inert the dormant original editor, with an
  explicit return; absent titles follow actual grouping/measure, authored titles
  stay literal, qualified context remains visible, unsupported comparison reasons
  name their actual projection, and retired trace/context requests abort. This
  corrected active ownership, not all outer navigation or visual density. Actual
  frames still show roughly 430px for two facet values and about 400px of nested
  ancestry/context at narrow width. Outer context-return consolidation was excluded.
- **314:** the supported string-group fixed baseline now uses existing aggregate
  acquisition. Actual alternating ClickHouse runs on the frozen GUI-authored query
  measured **four statements → two**, source bytes **73,680 → 258**, and executor
  DTO bytes **88,891 → 1,767**, retaining count 100 and aggregate fingerprint.
  Timeline five → three is transport-test support, not the measured live case.
  Selected rows remain inspectable; unsupported numeric grouping uses the full
  path up front, with no error retry. Aggregate receipts and warnings remain their
  own evidence: an unread row page has not been checked. See [read contract and
  measurements](FIXED_BASELINE_READS.md) and [journey](journeys/314-source-demand.md).

The actual reopened fixed-view Run preserved both queries and selected rows, used
one full selected read plus one aggregate baseline read and one source-free
comparison, and aborted a retired real baseline request without late comparison.
Its 1,768-byte baseline response was smaller; observed header time increased
366ms versus 160ms, so this is not evidence of a latency improvement.

Browser HTTP envelopes and SQL execution are separate measurements. The measured
service-entry discovery requests had different namespace selectors; similar time
bounds did not prove duplication. There is no demonstrated reason to delete one.
Timings and scan counts varied; no general latency or production-scale claim follows.

cannot be expressed clearly, deliver the contract/decision and retain manual entry;
do not ship a misleading shortcut or merge the source owners.

## Explicitly deferred contracts

Facet rendering remains a conditional 315 follow-up: its 1,000-value cap is not
a byte/DOM-work budget. If a legitimate long-value case demonstrates a problem,
measure equivalent property/attribute inputs, publish one budget, preserve exact
values/selection/focus, and refuse over-budget content explicitly. Loaded Find
matches (including zero) are distinct from the applied-population denominator.
No silent truncation/exhaustion claim or source read from local Find is acceptable;
readiness-only row rebuilding needs measurement before a scheduling abstraction.

Runtime remainder comparisons still require their admitted full group witness;
314 does not grant aggregate DTOs snapshot authority. New comparison families,
self-excluding facets and general applied-clause ownership need real task contracts.
Keep captured/held baselines unchanged rather than refreshing them as optimization.

More chart kinds, dashboards and whole-view WYSIWYG remain conditional on a concrete
missing task. Do not open a parity catalog, renderer migration, cache programme or
DataFusion/XTDB/runtime replacement. Shared deployment identity/isolation, retention/
restore and alert/SLO notification promises each require their own authorization,
source and operational contracts; compact controls do not deliver those features.
