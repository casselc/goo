# Product roadmap — 2026-11-08

Active execution order after the completed 376–378 breadth/depth/consolidation
sequence. This replaces the active queue in the [November 7 roadmap](ROADMAP_2026_11_07.md),
while retaining its delivery history. It adopts the source-grounded
[architecture](reviews/WHOLE_PRODUCT_ARCHITECTURE_378.md) and
[design](reviews/WHOLE_PRODUCT_DESIGN_378.md) checkpoint proposals.

The product loop remains **see current telemetry → isolate a population → follow
supporting signals → preserve or reuse the question/result**. Keep data and its
useful actions ahead of authoring and detailed explanations. Ordinary OTel sources,
exact questions and passive framework-neutral components remain the foundation.

## Adopted next sequence

### 379 — breadth: discover exponential-only services — delivered

The normal Services catalog now includes optional exponential-histogram points
under the same typed scope and global service/signal cap. Compact Scope controls
select recent or fixed UTC bounds and all/missing/exact namespaces. Shared strict
availability decoding distinguishes a missing optional table from successfully
empty matching data; errors and races fail the complete operation. Counts remain
exported points; observed exponential instruments remain unsupported for evaluation.

The real retained 13-point/eight-identity fixture is reachable through the normal
catalog row and service detail, then explicit instrument discovery. Ordinary
source counts, optional-source outcomes, narrow scope geometry and retired catalog
actions have focused and actual checks. See [validation](../VALIDATION.md),
[storyboard](../journeys/379-exponential-service-discovery-storyboard.md) and
[review](reviews/SERVICE_DISCOVERY_REVIEW_379.md).

### 380 — depth: follow exemplars from Saved native captures — next

The report and Go planner can validate captured native results, but Saved context
owners currently admit interval relations only. Add reported-exemplar relation
admission to the immutable Saved owner first. Do not imitate a live source adapter
or broadly enable callbacks in every renderer.

Preserve the authoritative capture/basis, export occurrence, exact namespace/window,
source-free staging and explicit fresh trace read. Back returns to the same held
capture without I/O. Unsupported/missing metadata and ambiguous source exports
remain unavailable. Extend service owners only if the same checked relation
contract fits; otherwise record that boundary rather than expanding this task.

### 381 — consolidate: share bounded JSONEachRow decoding

Native and record source readers repeat bounded line/object parsing. Extract the
small common decoder above the mechanics-only HTTP layer, with explicit per-family
row/byte limits and clear object/blank-line/trailing-data rules. Keep physical SQL,
query ownership, numeric semantics and lifecycle custody in their existing owners.

Use Go's current standard library where it simplifies allocation and iteration.
Independent boundary/property cases and actual source regressions must prove that
no family silently truncates, loses cause classification or inherits another
family's limit. Avoid a universal source framework or new configuration language.

## Deferred and removed from the active queue

General exponential evaluation remains deferred under the actual source and
representation gate. Service inventory visibility does not reopen it. Already
implemented record-review UI, log patterns, service defaults and ordinary reusable
views are not new feature proposals merely because older notes describe gaps.
Broader broker/consumer health still requires a concrete instrument contract.

This prerelease has no compatibility floor requiring legacy adapters or formats.
Go 1.27.3 is current in the workspace. Prefer ordinary public APIs and useful
internal stdlib improvements over clever type machinery for consumers. Keep the
shared components, storyboards, actual screenshots and tests current. Reassess
after this finite sequence or earlier if a material source/model boundary appears.
