## Product direction and review synthesis

Keep **current telemetry → isolate a population → follow evidence → preserve or
reuse the question**. Ordinary OTel works without a manifest. Existing live
selection/Keep, filters, comparisons, log patterns, trace waterfalls, discovered
service/resource dashboards, captures and finite display declarations are real
capabilities. Improve their connections rather than recreate these categories.

Design identified a needless distribution → record context → linked population →
view-settings detour. Architecture identified an existing grouped count-over-time
renderer/executor whose results cannot yet participate in shared timeline reuse.
Frontend identified further finite grammar opportunities, but adding every arm
would replace a roadmap with a feature catalog. Recent 388/391 held-return bugs
also show that terminal callback tests alone miss real application-wrapper gates.

Live Keep is already implemented by the shared tail's server-attested membership
workflow. The contrary Live documentation was stale and has been corrected.
Captured-record review, vocabularies and export also already ship; the historical
training proposal now distinguishes these from deferred tasks.

## 394 — delivered: direct distribution-to-customization progression

[394 delivery](DISTRIBUTION_CUSTOMIZATION.md) uses the existing flat count display
and trail owner, with actual log/span journeys, source-free held Back, save/reuse,
Bombadil and finite semantic/observed verification. The remaining execution order
is 396 after delivered 395.

User task: “This distribution is useful; customize and reuse its scoped view
without visiting a record inspection first.”

Expose a direct continuation from an accepted, compatible distribution into the
existing population workspace and its View settings. Reuse its complete question,
existing supplied-data contracts and continuation owner. Do not add another editor,
store or navigation manager. Start with the smallest profile actually supported by
the workspace; unsupported profiles remain explicitly unavailable.

Acceptance:

- One ordinary log and one span journey traverse accepted distribution → existing
  population/Customize → local presentation → save/reuse in a compatible destination.
- Preserve every typed predicate, environment policy, fixed bound, grouping,
  measure, offset/limit and exact source-read identity. Configuration reuse retains
  the destination's complete question; Run is explicit.
- Staging, local presentation and held Back do not read telemetry. If the existing
  workspace requires a new population read, stage it truthfully and wait for Run;
  never relabel a supplied distribution as fresh workspace evidence.
- Changed/failed/empty evidence, hidden or inert openers, pending replacement and
  superseded owners cannot acquire unsupported shares or continuation authority.
  Exercise the real producer-to-host wrappers, not only the final callback.
- Refresh storyboard, genuine desktop/narrow frames, relevant Bombadil actions,
  finite property cases and observed trace/model checks with rejecting controls.

## 395 — delivered: reusable grouped count-over-time displays

[395 delivery](GROUPED_COUNT_TIMELINE_REUSE.md) implements the grouped dataset,
profile, shared displays and existing save/reuse path. Actual logs/spans, exact
cell oracles, nested zero-cell continuation/Back, UI/accessibility review,
property/wire cases and observed model/actor validation pass. The source budget
is 1,000 observed cells; dense materialization is separately bounded at 1,920.
The remaining execution order is 396, then whole-product review.

User task: “Keep this service or route breakdown over time and reuse its display
on another compatible fixed population.”

Existing grouped execution and `grouped-time-series` small multiples/heatmap are
not missing. Timeline declaration admission currently excludes grouped time
series. Before implementation, pin a finite supplied-data contract for **count
only, one qualified grouping, existing fixed intervals**. Preserve current limits
(eight groups, 1,000 cells) unless separate evidence justifies a change.

This is a semantic feasibility gate: establish exact group×interval row identity,
category completeness, absent-bin meaning, partial final intervals and independent
read disagreement. Known empty bins must differ from unavailable observations;
all-zero invented series must remain refused. If the existing source cannot attest
these meanings, stop and revise this cut rather than manufacture completeness.

After that gate, reuse the existing declaration/store, renderer and workspace.
Support the finite compatible visual choices and local presentation controls;
retain canonical typed group values as scope keys. No new query engine, arbitrary
template expansion, numeric/duration aggregation, summed percentiles or automatic
native adoption belongs here.

Acceptance includes Go/JS/API positive and refusal vectors; exhaustive raw
category×interval count oracles; missing/empty/Unicode groups; zero/unknown/changed
states; exact destination compatibility and whole-question preservation; no-read
Inspect/Apply/local changes; explicit Run; genuine small-multiple/heatmap frames
and current-owner return checks. Group completeness never proves full ingestion.

## 396 — consolidation: composed held-staging boundaries

User task: “Returning to held evidence leaves safe local investigation actions
usable, without reviving an old read or publication.”

Bound the work to the concrete ordinary exploration → distributions → population
wrappers touched by 394/395 and the reproduced 388/391 retirement failures. Add
composed acceptance cases that execute both producer and application gates across
suspend, Back, repeated staging, replacement, hidden/inert state and stale replies.
Verify zero reads for approved staging and continued refusal for retired
acquisition/publication. Include failed replacement with prior accepted evidence.
Exercise a held parent's local kind/Find edit followed by Save/reopen: the saved
declaration must match the visible draft without renewing source actions. A
read-only phase must be explicit; it must not silently discard a visible edit.

Clean up duplicated predicates only where actual repeated orchestration has the
same ownership semantics. A regression-only closure is acceptable when no safe
shared helper is justified. Do not build a universal session manager, generation
framework, request router or source client. No performance improvement is claimed
without a measured path and benchmark.

This cut closes with focused production-wrapper regressions, the relevant actual
journeys and observed admission/model controls. It does not launch a testing
platform or rewrite unrelated navigation.

| --- | --- |
| Live exact occurrence Keep | Delivered through shared tail membership; correct documentation/discoverability rather than rebuild retention. |

| Saved/service gauge nearby-record continuation | Valid retained-sample/custody follow-up, deferred to avoid another native-only sequence; ordinary gauge context already ships. |

| Selector byte/NUL/Unicode admission consistency | Reconcile against 393's typed-input finding; fix proven boundary defects, not a universal validation engine. |
| Review-task discovery / verified kept-occurrence review | Deferred. Existing captured-record review and export are delivered; do not impersonate a kept occurrence with a fresh capture. |
| Exponential histograms, arbitrary executable kinds/WYSIWYG, tenancy/presence, alert delivery, broad DB/broker health, warehouse/new stores | Separate design/source/platform gates, not implicit additions to this queue. |

Use Go 1.27.3 and modern standard-library facilities where they simplify a touched
path; no compatibility floor or legacy formats constrain this prerelease. Keep
advanced internal machinery out of ordinary caller APIs. Profile before pooling,
parallelizing reads or claiming performance wins. Keep heavy jobs serial and retain
only useful current documentation/acceptance artifacts, preserving stores.

Reassess the whole product after 396, or sooner if feasibility or actual use
invalidates this order. Do not automatically append the deferred candidates.
