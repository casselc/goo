# Roadmap after the 402 checkpoint

The next finite cadence is **403 breadth → 404 depth → 405 consolidation**, then
whole-product review. See [review reconciliation](reviews/ROADMAP_RECONCILIATION_402.md)
for adopted and deferred candidates, and [validation](../VALIDATION.md) for executed
results. The preceding [399 cadence](ROADMAP_2026_11_10_CHECKPOINT_399.md) delivered
compact summary authoring, retained service-gauge continuation and shared-table context.

Keep current ordinary OTel → isolate a population → follow evidence → preserve
or reuse the question/presentation. Manifests remain optional. Missing data,
independent reads, bounded pages and immutable custody retain distinct meanings.
This prerelease has no legacy-format obligation; current Go is 1.27.3.

## 403 — breadth: continue a trace search beyond the first page

User task: “There are more matching traces. Let me inspect the next ones without
rebuilding the search or losing its conditions.”

The current search sorts IDs and reads `limit+1`, but exposes only a limit notice.
Add bounded continuation through the existing search owner. Decide position versus
saved authored intent explicitly before changing request/capture shapes. Bind the
position and echoed result to the full canonical conditions, environment policy,
fixed window and limit. Preserve exact lexical trace identity, qualified witnesses,
and totals evaluated before position filtering.

Each page is a fresh source read and basis. It is not a stable snapshot: concurrent
ingestion/corrections can change membership, and traversing pages does not prove a
complete union. No implicit background paging or whole-trace completeness claim.
Keep existing captured searches immutable and source-free to reopen. Validate actual
source results, full Saved/store/API carriers, stale/hidden/pending controls and
held child/Back. Stop and resolve any conflicting capture-family admission before
implementation. Refresh real desktop/narrow journey frames and actor/model checks
where the changed owner requires them.

## 404 — depth: reuse an ungrouped record/summary template

User task: “Reuse these few key facts beside records in another compatible scope,
without making up a grouping.”

Extend the existing template arm with a finite records-plus-summary profile, using
400's supplied dataset and passive component. Start count and ordinary span-duration/
recorded-status fields; numeric bindings join only if exact qualified field/type/
unit/parse compatibility is admitted through every carrier. No new SQL or evaluator.
Records remain required; do not manufacture aggregate/grouping aspects.

Settle the existing page-zero template-root requirement explicitly; preserving
paging settings does not automatically admit arbitrary continuation pages.
Inspect/Apply imports presentation only and preserves the destination's complete
predicate, environment policy, bounds, fields and paging. It grants no source lease,
read, capture or completeness claim. Validate declaration, expanded composition,
store/API carriers, incompatible profiles, omissions/null/unknown fields and current
application owners. Actual save/reopen/Apply/Run/held Back must preserve selected
field order, zero/unavailable/support semantics and read budgets. Keep source-free
configuration steps separate from explicit execution/publication.

## 405 — consolidation: one ClickHouse parameter wire encoder

Share only the pure escaping function currently duplicated in exploration and
measurements. Compare existing behavior first and use actual cross-family source
round trips for backslash, tabs/newlines, other ASCII controls and Unicode. Include
independent literal-value expectations and malformed/refusal controls as appropriate.
Use the same typed source parameters and preserve source budgets, settings, error
handling, decoders and policies in their owning families. No identifier interpolation,
query semantics change or performance claim belongs in this cleanup.

Keep heavy jobs serial and preserve the runnable lab, telemetry and stores. Finish
and review each milestone before advancing; defer unrelated ideas until the next
whole-product review rather than growing an unbounded execution queue.
