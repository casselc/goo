# Roadmap after the 423 checkpoint

The latest cycle delivers contextual Activity facet entry (421), atomic
multi-value staging (422), and measured scope-snapshot consolidation (423).
[Validation](../VALIDATION.md) records execution;
[product/UX review](reviews/PRODUCT_FLOW_CHECKPOINT_423.md) and
[architecture review](reviews/ACTIVITY_SNAPSHOT_REVIEW_423.md) inform this sequence.
The product remains **current telemetry → isolate → inspect/compare → preserve/reuse**.

This is an adoption cycle over existing primitives. Counted facets, broader
questions, selected/rest comparisons, scope recall and stored evidence already
exist. The gaps below concern reaching them naturally from the current
investigation; they do not justify another query engine or dashboard.

## 424 — breadth: explicit contextual field-constraint editing

From an inspected/faceted field, expose the exact applied constraints that keep
other values out of view. Reuse the existing filter editor or stage a named
broader fixed question. Choosing an entry stays local; an explicit Apply/Run
acquires the broader population. Never silently remove a predicate or feed
broader counts into the unchanged 422 editor.

Bind any removal/edit action to the original question lease and an exact clause
path plus canonical content. When several conditions mention a field, make the
choice explicit. A mixed-field Boolean group must not lose an arbitrary member
or its first matching child. Preserve every unchosen constraint, qualified field
namespace, typed environment policy and the stated window. Validate the full
result before atomic staging; stale/hidden actions refuse without changing the
held population. Keep keyboard/mobile return and explicit source budgets.

## 425 — depth: counted selection into existing selected/rest comparison

Offer a natural comparison handoff from the current categorical selection to the
existing fixed selected/rest workflow. Derive the subset and its complement from
bounded generated categorical intent within the original parent scope. Do not
introduce arbitrary Boolean complement or treat counted snapshots as comparison
operands. An explicit Run reads both populations independently.

Reuse current ordinary-count profile, window and AST limits. Preserve missing,
empty and literal alternatives; explain that the rest is relative to this parent
and window. Retain independent read facts, known-zero/diagnostic states and the
actual opener on Back. Unsupported profiles must remain clear refusals.

## 426 — consolidate: preserve, recall and retained-return conformance

Exercise the end-to-end brownfield loop through scoped stream, inspection,
compound facet, explicit comparison, preservation and reopen. Reuse existing
capture/recall/return owners. Keep query intent distinct from retained observations
and immutable evidence; reopening or returning must not silently reread.

Address demonstrated control/focus/prose drift in shared components rather than
adding a new shell. Cover desktop and narrow keyboard workflows, exact scope/
clock/custody facts, source budgets, native stale-action checks and the current
executable storyboards. Refresh the next whole-product checkpoint from this
experience rather than accumulating vendor feature lists.

## Boundaries

Monitoring delivery, source authorization/tenancy, arbitrary executable kinds,
classifier training, warehouse lowering and broader native histogram work retain
their separate operational/design gates. These are not displaced by a new
feature list. The older [417 roadmap](ROADMAP_2026_11_13_CHECKPOINT_417.md) records
the completed cycle and remains historical context.
