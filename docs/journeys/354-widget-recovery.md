# Recover one service widget

A failed supported widget offers an explicit Retry for its original fixed question. Recovery must not replan the overview, reread healthy siblings, replace their DOM, or change their independent source receipts. This does not establish service health or complete telemetry coverage.

The journey emits genuine OTLP spans, logs and a gauge into ClickHouse: service A has three 10ms spans, two logs and a gauge observation of 42; service B has two spans, one log and a gauge value of 7. A scoped upstream HTTP proxy forwards successful SQL unchanged. Its planted 503s fail one record-aggregate group read and one supported native sample read, rather than fabricating an API response.

1. Open the scalar service overview. Fail its span widget while logs and the gauge remain observed. Inspect the typed refusal, then Retry exactly that span question. Preserve sibling article/pre identities, open disclosures, receipts and read clocks.
2. Open the same service under a typed current-only named policy. Native support keeps its existing current-key contract. Fail and retry only the gauge widget; retain both record widgets and the original fixed measurement definition.
3. Hold a genuine successful record retry response after backend completion. Leave through the Explore workspace while that retry remains pending; observe the original request abort. Return to Services and open service B. Releasing the old response and invoking captured old callbacks must not change B or issue another source request.
4. A focused Bombadil campaign independently follows an actual saved inventory into a record-widget refusal and recovery. Positive completion requires a visible recovered heading, exact count/duration, unchanged sibling DOM/receipts, no replan and one explicit retry request.

Record aggregates and native measurements keep their own clocks and grains. Public setup captures and direct ingestion/oracle reads are separate from browser request totals. The observed model covers the selected failed-slot lifecycle; generated state/swarm tests cover the shared two-worker scheduler and ownership interleavings.
