# Recent and pinned scopes

Executable: [recent-pinned-scopes.spec.js](../../journeys/recent-pinned-scopes.spec.js).
The journey uses an isolated Go server and ordinary OTLP logs in ClickHouse.
The validation record reports which checks were actually executed.

An operator has found a useful log population and wants to revisit it without
rebuilding its filters. The picker distinguishes reusable configuration from
results held in this tab. Nothing in query history constitutes captured evidence.

| Step | Operator interaction | Objective check |
| --- | --- | --- |
| Investigate | Run a fixed question over ordinary logs. | The result count matches independently selected source records; the retained page is bounded separately. |
| Preserve intent | Open Recent/Pinned and pin the question. | No source request; only validated question configuration is retained. |
| Change scope | Stage a different fixed question. | Staging does not run the question. Its time window and filters remain explicit. |
| Return to results | Choose the earlier held visit. | Original supplied rows return without a source request. Held results are tab-local and disappear on reload. A fixed deep link can create one new staged visit. |
| Reuse intent | Stage the pinned configuration. | An editor opens with the exact fixed window and selector; Run remains explicit. |
| Reuse Activity | Stage a saved rolling scope, pin it and recall it. | Staging reads configuration only. Dirty signal changes block replacement; explicit Start alone begins polling. |
| Return from Activity | Pause Activity and choose the held fixed visit. | The same retained rows return even when that visit was already the current fixed owner. |
| Keep locally | Enable browser history, then reload. | Only opted-in configuration survives. No telemetry bodies or retained result objects are serialized. |
| Forget | Clear recent history and unpin a scope. | History and pins have separate, explicit deletion controls; deletion performs no source read. |
| Narrow screen | Open the picker at 390px and 320px. | Controls remain contained and named; configuration, retained results and explicit Run remain distinguishable. |

Browser memory is useful immediately. Browser persistence is opt-in and is not
an authenticated per-user store. Do not enable it on a shared browser profile.
Clearing this history does not delete captures, saved definitions, or telemetry.

Screenshots are generated by the executable journey into
`docs/journeys/screenshots/recent-pinned-scopes-{1440,390,320}.png`.
The ignored `artifacts/recent-pinned-scopes/report.json` records source counts,
actual API/SQL calls and local-action read budgets. With `GOO_SCOPE_HISTORY_BOMBADIL=1`, a separate 30-second actor pins, stages,
unpins and forgets a real staged question without reading telemetry. Its unique
trace directory stays beside the report. Runtime cleanup occurs in
`finally`; the telemetry source and existing stored evidence are preserved.

The presentation refinement gives reusable and held scopes the same filter,
identity and compact UTC hierarchy. Return/Stage actions keep contextual accessible
descriptions; exact bounds remain in tooltip/accessible detail. The executable
journey regenerates the desktop/390/320px frames with unchanged local read budgets.
