## 314 measurement cut

Reuse the actual 313 journey's request/response/checkpoint collector for HTTP
counts, canceled requests, response bytes and elapsed times. It already separates
Activity, service entry, facet, cohort and trace actions. Freeze one explicit time
window and admitted query; keep discovery's two identical requests separately
identified until their owner and freshness roles are understood.

The existing `cmd/goo-read-audit` is the minimal SQL measurement seam: it wraps
`Source.Client.Transport`, counts actual executed statements and consumed response
bytes, records durations and allowlisted ClickHouse summary counters, and hashes
SQL without publishing statements, parameters or records. Its current modes are
full explore, counted values and record aggregates; it does **not** measure the
whole browser flow, discovery, page, or cancellation. Do not present a compiled
statement table or a replayed query as measured UI-to-SQL attribution. First pair
one captured, fixed comparison-operand query with full/aggregate audit runs against
the same source. Keep browser HTTP observations and these executor measurements
explicitly separate; add a bounded test-only transport fixture for the selected
operand when checking the exact statement budget.

Only then decide whether that operand can use existing aggregate acquisition.
Acceptance is unchanged admitted query/count/groups/duration/status/series,
independent receipt and certainty semantics, equal aggregate fingerprints where
applicable, no fabricated rows/full snapshots, and actual before/after statement
and byte counts. Timing is exploratory unless repeated under controlled inputs.
Verify cancellation and terminal inconsistency remain honest. Add one regression
budget at the changed owner, rather than a global latency threshold. If there is
no supported saving, record the result and retain the current executor. General
transport observability, cross-request tracing, caches and density cleanup remain
outside this experiment.
