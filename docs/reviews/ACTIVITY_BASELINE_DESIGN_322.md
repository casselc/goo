# Checked saved baselines across Activity — design 322

Status: bounded source and all three final actual frames accepted.
Read with [saved Activity baseline references](../SAVED_ACTIVITY_BASELINE.md),
[Activity explanations](../ACTIVITY_EXPLANATIONS.md) and checked record policy.

## Bounded task and existing gap

A responder using an effective, empty or unreported environment wants to reuse
saved baseline evidence from Activity, rather than abandon the supported record
scope or copy a name into a current-only query. Complete the existing latency
baseline and saved-scope explanation paths under checked semantic equality.
This is continuity of existing functionality, not another picker, catalog,
comparison language or metric profile.

Current source explicitly rejects selector-bearing captures in both Activity
baseline loading and Activity explanation loading, despite existing checked
question/equality helpers and Activity publication validation. Baseline catalog
and capture-title labels also read the legacy environment string directly,
producing misleading blank labels for typed scope. Remove those obsolete gates
and name-only assumptions directly; the prerelease needs no compatibility shim
or parallel baseline format. Preserve existing distribution/receipt validation.

## Two meanings that must remain distinct

**Latency Baseline uses frozen evidence.** It resolves an exact stored raw-span
duration capture and compares its stored full distribution with an explicit
current Activity latency read. Show **Frozen baseline** and **Activity window**,
with original baseline event bounds/source-read clock, capture custody clock and
current Activity bounds/read clock in the existing local details. Resolving or
retrying a stored baseline must never reread its source question.

**Explain → Saved capture scope reuses a question.** Loading the exact capture
stages its checked saved query; no saved counts or field frequencies become the
new explanation. Say **Saved scope · reread on Run** or the existing equivalent.
Explicit Run explanation rereads both fixed populations; late arrivals can change
the baseline count. The original receipt/custody/source clocks are provenance,
not the new baseline observation's clock. Do not label this as Frozen baseline.

Keep these actions in their existing surfaces. Their shared capture ID does not
justify merging their observation owners or presenting one ambiguous universal
Use baseline action across the product.

## Checked scope and readable labels

Use the existing environment formatting/equality helper everywhere: selection
labels, capture title, saved Activity reference, scope facts and mismatch errors.
Show named current-only versus current/legacy precedence explicitly where they
can differ. Empty label is not a blank/Any input; unreported is not unknown/null
catalog metadata. Current-only typed named selection may equal its legacy wire
name semantically; effective named with the same text does not.

Frozen latency keeps its supported span/raw-duration grouping, canonical full
accounting and observed/no-data admission. Native metrics, unknown/changed results
or unsupported distribution shapes still refuse. Saved-scope explanation keeps
its existing same signal/checked environment requirements and complete predicates,
fixed bounds and per-field limits. Neither path silently substitutes another
capture, strips a selector, broadens time or invents missing/empty values.

A readable mismatch says the captured baseline uses a different environment
policy/scope; it must not claim only a different environment name when names
match. Catalog metadata helps find candidates, but actual receipt admission
remains authoritative. Unknown metadata must not be formatted as unreported.

## Interaction, saved references and failure

Existing Load saved baselines / Use baseline and saved-scope ID controls remain.
Opening metadata or resolving a receipt performs stored reads only. Start stream,
Show latency and Run explanation retain their explicit source effects. Saving an
Activity view pins the exact baseline capture ID, not copied data or an automatic
refresh policy. Reopening stages selector/reference with empty observations; Start
and latency acquisition remain deliberate.

Unavailable/incompatible receipt errors stay local and actionable. Retry uses the
same intended reference and held current data, without a hidden source reread.
Do not erase a valid saved pin, replace it with the current scope or let a late
old response overwrite a newer selection. Clear is explicit; pause/leave/scope
change retires callbacks through the existing request/owner leases. Returning to
Activity preserves held records and visible focus without resume or recapture.

## Consolidation boundary

Reuse existing checked scope/capture admission, environment labels, comparison
components and native disclosures. A small shared pure helper is justified only
where both loaders need the exact same bounded question/policy fact; it must not
collapse frozen-result and fresh-query semantics. Do not create a universal
baseline manager, new persistence model or new backward-reader branch.

## Acceptance as one real continuity task

Capture an actual typed raw-span duration distribution, then use its ID as an
Activity latency baseline and save/reopen the Activity reference. Verify frozen
counts/buckets remain exactly stored while current Activity has its own new read.
Use that same capture as an explanation scope; ingest a late matching record and
Run explanation to demonstrate a fresh baseline count while the frozen latency
capture stays unchanged. Both meanings and all relevant clocks must be readable.

Cover effective named, empty and unreported checked policies, current-only
semantic equivalence and same-name foreign-policy refusal. State native versus
unit/property coverage precisely. Metadata/load/save/reopen/return must not query
telemetry; explicit Activity/explanation acquisitions keep their actual budgets.
Exercise unavailable receipt retry, replacement and late response without losing
intent or changing a held parent. Update compact actual frames/storyboard for
frozen distribution, scope-reread explanation and restored saved reference.
No product/browser edits are needed merely to review this contract.

## Frozen source acceptance

The final source removes the obsolete selector-bearing refusals directly while
retaining exact capture/result admission and checked environment compatibility.
Catalog options use the shared checked policy formatter, and incompatibility
errors name policy rather than only legacy environment text. Frozen comparison
and saved-scope explanation keep their existing distinct labels, source/custody
facts and explicit acquisition owners; no new control or adapter was introduced.

The latency capture title uses the full checked policy label only when the
result fits the existing **120 UTF-8 byte** title contract; otherwise it is the
stable **Latency baseline** title. This is presentation fallback, not a truncated
selector or changed capture question. Actual checked scope remains in the query
and read facts, so a long/multibyte environment label cannot break Capture or
silently reduce policy identity.

Source UX review has no blocker. Final actual-frame acceptance is recorded below;
execution/campaign reports remain separate from source inspection.
