# Attribute refinement 442 acceptance

Accepted after source follow-up for the bounded [attribute-refinement contract](../ATTRIBUTE_REFINEMENT.md). This review covers shared field intent, attribute details, record columns, observed-field suggestions, categorical facets and their staging adapters. It does not claim a whole-product accessibility audit or physical assistive-technology testing.

The shared helper constructs ordinary validated predicates and detached field references. Include selects the exact reported value; Exclude selects its complement, including a missing key. CEL `.ne()` deliberately remains a reported-only comparison. The same literal key in resource and record attributes stays qualified. Empty string is a reported value and never stands in for missing. Presence gestures use the existing include/exclude-null selection representation, so population and comparison owners retain their established grouping and publication rules.

The reviewer inspected admission before mutation in Activity and fixed exploration. Rejected refinements no longer retire checked authoring first; Activity validates the combined predicate budget before replacing a draft. Existing parent predicates remain under AND, and source acquisition stays in application adapters. Shared components stage intent; opening disclosures, inspecting supplied values and choosing a condition do not themselves read telemetry. Explicit executing actions remain separate.

Attribute actions stay inside the shared compact native disclosure. Missing custom table cells expose presence actions without manufacturing a value action. Observed-field suggestions offer reported/missing independently of whether a missing value occurred in the loaded page. Categorical presence actions use the actual shared `components.actions` implementation, including Escape and close-to-summary focus behavior. Follow-up source inspection confirms that column and categorical presence callbacks now use `nativeControlReady`, resolving the initial disabled/inert/fieldset guard finding.

The reviewer independently ran five focused test files for shared intent, presence facets, attribute actions, columns and Activity filters; they passed without skips. The implementation owner separately reports a passing real-OTLP logs/spans browser journey with 44 CEL/refinement reads and two visual-baseline reads, plus a passing 55.5-second inspection/Bombadil journey. The latter asserts the new presence-menu completion marker, so its new qualified-field invariant is exercised rather than accepted only on an empty menu set. Bombadil opens, verifies and Escape-closes the menu; it does not click a refinement action or dispatch a source query for this added stage. Runtime cleanup was reported successful.

The owner also reports passing existing querycel unit checks (0.062 seconds), Hegel parity/partition checks (0.368 seconds), and an earlier full UI suite with 1,855 passing tests. Shared-menu reuse subsequently required a mock export update; the targeted render test passed afterward. The final full-suite rerun and responsive screenshot assertions belong in [validation](../../VALIDATION.md), not as independently executed claims in this review. The reviewer did not rerun the live browser/source environment or measure performance improvements.

No blocking source-review findings remain within 442. Numeric attribute parsing/ordering and broader query-language coverage retain their separate contracts; this change does not infer SDK numeric types from exporter string maps.
