# CW1 acquisition consumer review

The [portable acquisition fixture](../../verification/gotogether/testdata/cw1/contract.md) is accepted as a bounded consumer handoff for upstream CW1. It is preparation for literate extraction, not an implementation or acceptance of an upstream Markdown runtime. The existing [source model](../../verification/gotogether/model/acquisition.qnt) remains authoritative until that runtime exists.

The reviewer inspected the authored Quint and binding fences, model/binding/scenario snapshots, manifest, all 23 recorded protocol events and the fixture replay test. The manifest pins gotogether `a1a90fe5653db07cbf6cc467021bda18e4b27d79`, identifies capture `1a04dbf5ce4e`, and gives SHA-256 digests for the five snapshot files. The test checks those hashes, source snapshot equality and fence equality before using the existing source/compiled replay and negative controls. This detects snapshot drift; it does not exercise CW1 extraction or document-line diagnostics.

The recorded question, service, environment, selected detail and resource attributes use synthetic fixture values. The log contains route references rather than full URLs and no authorization headers, credentials or apparent personal data. Selected DOM detail includes one synthetic raw source row; the fixture does not export all 240 OTLP points. Original timestamps, invocation IDs, responses, navigation epochs and raw interned strings are retained. No recorder is used to synthesize a replacement run.

The implementation owner reports that the fresh capture passed the live Playwright journey, native source gate, source/compiled shadow controls and Bombadil admission. The reviewer inspected the retained fixture and implementation rather than independently rerunning that live environment. Capture provenance records 240 OTLP points, 24 native SQL assertions and database cleanup. Static replay checks the recorded bounded DOM ownership and completion projection; it does not rerun those SQL assertions, prove collection completeness or establish arbitrary transport-to-DOM adoption causality.

The named scenario is preserved separately from the weaker YAML simulator outline. An aborted code-0 response completes its own invocation; an unanswered call remains pending. The final `drained` event is an explicit observation from the recording driver, interpreted by the preserved bridge. EOF alone cannot establish settlement, and static replay cannot independently verify that the original source meter and observers actually drained.

CW1 acceptance still requires upstream extraction of the identified model block, a deliberately broken invariant reported at its authored document line, stale generated-output refusal and replay of the real log while retaining the separate native source gate. The portable snapshot and checksum checks do not establish those future capabilities. No promotion to a sole verification gate or performance claim follows from this review.
