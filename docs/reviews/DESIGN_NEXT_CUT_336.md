# Next product cut: narrow a comparison without leaving it — 336 review

Status: source/design recommendation, not implemented functionality. No browser,
source edits, builds or runtime measurements were performed for this review.

## What already works

Activity is the live log/span entry point. It has applied filters, local loaded
Find, selected-record Keep, numeric/latency selection, fixed-window analysis and
an explanation workflow with time brushing. Those are not missing features.
333 stages a full previous-window count pair; 334 follows either group into
supporting records; 335 preserves the task across passive history notifications.

Reusable categorical facets already have a checked declaration, passive element,
explicit full-scope value read, typed Include/Exclude tray, and Go/YAML admission
(310/311). Facets and count comparisons cannot currently coexist. The fixed-view
editor says “Remove the facet before adding a comparison”; some comparison
adoption explicitly removes the facet control. The documented grammar refuses
this combination even when the control is hidden.

That boundary interrupts an ordinary investigation: “This service changed; is it
only one route or tenant?” Today the user can open one side's records or configure
another question. They cannot retain a contributed facet beside the fixed pair
and apply the same category restriction to both windows.

## Recommended general-purpose cut

Allow one existing categorical facet with a **fresh fixed-query count pair**.
Reuse the current facet declaration and value-count acquisition, selection tray,
comparison presenter, question AST, composition editor and explicit Run path.
Do not add another drawer, chart, filter language or acquisition manager.

The facet's value counts initially describe **Selected window** only. Label that
basis where counts are shown. The pending selection clearly says **Both windows**:
applying the typed Include/Exclude delta conjoins it with each operand's complete
original predicate, preserving each operand's exact fixed bounds and environment
policy. Authored selector differences remain differences; the UI does not imply
that a common additional filter makes two original scopes identical.

Staging is local. Only the explicit apply/run action reads both revised questions.
Keep the prior supplied pair visible until replacement is admitted, and retain a
clear paused parent/Back path. Save/export preserves both revised definitions and
the facet declaration, not the observations or temporary choices.

Frozen/captured baselines, held-parent/Rest comparisons, unrelated measure kinds
and native metric streams keep their existing contracts in this cut. Do not
silently mutate a frozen operand or narrow only the selected side under an
ambiguous generic Apply label.

## Acceptance journey

1. Start with ordinary OTel logs or spans and compare the completed previous
   window. Add/reuse a contributed string facet such as `http.route`.
2. Explicitly read its values; counts identify Selected window and full-scope
   evidence, never the loaded record buffer or a Find match count.
3. Include a route, then exclude another value or Missing. The existing tray
   states Both windows. No source read occurs while staging/undoing/clearing.
4. Apply explicitly. Both questions retain their distinct exact UTC windows,
   typed environment policy and whole original predicate trees. Both acquire
   independently; the supplied comparison remains descriptive, not causal.
5. Inspect a changed group's supporting records and return to the revised pair,
   facet state and focus. Save/reopen stages the same declaration without reading.

Required proof: generated Go/JS admission for atomic two-operand predicates and
missing/empty semantics; negative controls for unsupported frozen/Rest contexts;
real source counts exceeding the loaded page; native keyboard/focus and return
checks; bounded actor completion. Narrow layouts must show the task and applied
scope before a long list of controls. No new generic toolbar is required.

## Following depth cut

Consider values present only in the previous window. Read both full populations
explicitly and show a union with actual operand labels and side counts, permitting
narrowing a disappearing category. Reuse full comparison group witnesses where
compatible; distinguish observed zero from unavailable/no-data. This follows the
same investigation rather than introducing a separate anomaly-score catalogue.
