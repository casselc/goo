control. Require the current configured comparison, both checked whole operands,
matching applied pair identity, visible/connected current owner and no unresolved
query/selection/source draft or pending read. Captured baselines, temporary
selected/rest comparisons and specialized histogram/status modes remain outside
this entry. Do not infer completeness from matching counts or loaded row pages.

not a reconstructed service/group sample. Preserve each whole original predicate,

checked environment across sides; predicates and intervals remain independent.
The existing explicit field chooser admits one–six qualified fields, with bounded
keys and no duplicate/duration-bucket field. Opening/choosing fields performs no
source acquisition.

`PlanExplanation` retains those full questions in its Request and derives count

group projections, reset offset to zero and use the existing bounded count-plan
limit. This is deliberate projection, not loss of original scope. Baseline and
selection count reads plus independent field grouping reads produce new clocks
and bases. Do not replace the held comparison's receipts or compute explanations
from its row page. Ordinary exact count/share changes remain the existing engine.

result is **population composition**, not attribution of the mean change,
percentile arithmetic, causal evidence or significance. Keep that qualification
at the entry and result. Exact sum/count remains the mean pair's authority; no
mean weights are injected into count/share explanation.

Use actual operand roles (Previous window or Fixed baseline window, Selected
window) consistently in the immediate explanation context and side actions.
Presentation labels are not source identity or a new request/custody field. The
existing stored explanation can reopen with neutral Baseline/Selection labels
and its complete original questions/UTC bounds; do not claim a saved label format

## Ownership, partial data and custody

The explanation owner must retire pending source/planner work on parent drafts,
Run, comparison replacement/hide, child departure, route departure and disposal.
Late success/refusal cannot publish into a new pair or same-scope ABA revisit.
Close/Cancel preserve explicit reacquisition; never automatically rerun.

Returning from the side child restores completed observed explanation/fields and
the held pair without source IO. The current `snapshot()` contains fields/request
only, so preserving completed observed state requires a bounded owner extension:
e.g. snapshot result/local state and dispose/remount with its existing saved-result
path. Fresh handlers bind the current parent; saved callbacks from the disposed
owner stay inert. Do not leave a permanently stale canAct closure or revive old
source handlers by changing a shared generation. Result token expiry is unchanged.

A partial/unavailable explanation field retains its independent read state and
withholds comparable rows/ranking for that field. It is not zero/no-data or proof
of missing instrumentation; usable fields remain usable. Source-budget refusal,
malformed response and inconsistent reads retain the engine's current semantics.
No new broad failure taxonomy or engine rewrite is required by this entry.

Save observed explanation promotes the existing server-held result token without
rereading telemetry. It must not archive browser-supplied counts or silently rerun
a missing/expired token. Once the user submits a save, publication can finish even
if display ownership retires; late acknowledgment must not navigate/rewrite a
newer task. Unknown acknowledgment is not authorization to retry automatically.
Opening stored custody remains separate from rerunning its scope.
