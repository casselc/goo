# Held chronology acceptance

Independent architecture, OTel, UX and accessibility review accepted the optional
held view after source and fresh-frame follow-ups.

The view consumes Tail observations from multiple polls, not a fabricated single
record page or evaluated aggregate. Original selectors, per-record windows and
read clocks remain distinct from each lane’s latest read. Preservation tokens stay
outside passive data. Exact event ordering preserves duplicates, stable ties and
an explicit unplaced population without inferring causality or completeness.

Review corrected two ownership/provenance edges:

- A lane with retained history but no latest completion now says **latest read
  unavailable**, rather than claiming it was never read. An empty unconfigured
  descriptor keeps a null selector; it never borrows the pair’s scope.
- Pause and Hold capture the global and both lane epochs. Synchronous replacement
  during one pause cannot cancel or adopt a replacement sibling. Analyze rechecks
  its ownership lease after pause before staging the fixed question. Cached
  inspector actions reuse the actual retained button rather than a discarded node.

Fresh 320/390/1440 chronology and 320/390 inspection frames show a visible Back
control, independent source facts, UTC timestamps, Log/Span labels, compact Find/
paging and readable original-window inspection. Source, model, component and owner
checks passed independently; no remaining scoped blocker was reported. This is not
whole-product accessibility certification.

Real OTLP journey `5143e2393c66` passes against the final runtime, including native
Quint replay and nine rejected negative controls. Existing lane-filter regression
`3eb2fd01e8f6` also passes on the identical runtime, including 15 rejected controls. The browser and independent
physical-source oracle check 55 logs and 55 spans, duplicate conservation and
nanosecond ordering. Synthetic diagnostic timestamps and null-lane profiles are
separate unit/property evidence, not fabricated source data.
