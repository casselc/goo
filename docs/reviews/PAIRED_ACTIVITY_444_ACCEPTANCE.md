# Paired Activity 444 source acceptance

Accepted after follow-up source review of the paired Activity implementation,
its shared selector planner and the existing Tail ownership seam. No blocking
source findings remain within the bounded 444 contract. Final live execution,
responsive frames and native observed-trace results belong in
[validation](../../VALIDATION.md); this review does not independently claim them.

The planner validates the complete shared predicate for both logs and spans
before either connection can start. Environment policy and branch structure stay
explicit and detached; All-environments and signal-specific filters refuse as a
whole. The UI's `both` choice remains session composition, never a new source
query signal or a single-signal saved Activity view. Environment discovery is
inactive in paired mode, so it cannot accidentally send that composition marker
to a single-family API.

The coordinator owns two ordinary tails. Each retains independent source status,
window, connection, occurrence keys, loss and Find state. Local callbacks carry
detached owner/signal metadata; StreamEntry no longer refreshes its singleton
tools from every global tail event. Existing comparison, explanation and other
single-tail tools stay bound to their original owner and are inactive for the
pair. No combined count, health state or authoritative cross-host chronology is
introduced.

Inspection and fixed drill-in retain their originating family, selector, captured
window and lane epoch. Final source follow-up confirms the handoff uses the
existing `Tail.recordQuestion`, which retains the complete parent `where`; the
trace-context `inspectionQuestion` helper intentionally omits that predicate and
is not suitable for this action. Inspect pauses its lane; navigation pauses both. Return
reveals the retained DOM before synchronizing control availability, restores
scroll/focus without reconnecting, and has a visible control/environment fallback
when an old opener is retired. Recalling a saved single-family Activity first
stops the pair rather than merely hiding live connections. Its modified-scope
confirmation is one movable node: it remains visible in the shared paired toolbar
or the single-view disclosure as appropriate. Native owner/generation/hash guards
protect Keep/Discard. Keep retains the paired scope at `#explore`; Discard
explicitly pauses both lanes before staging the single-family view. Pausing an
uninitialized pair is a no-op, so initial lane state is not invented.

Follow-up source inspection confirms active-owner and native-control admission
for Tail user callbacks, including Resume/Retry, Find, row actions, Pause/Close
and preservation controls. Imperative pause/reset remain available for parent
lifecycle management. Invalid shared drafts keep Apply disabled using the actual
pair admission error. These guards preserve custody when callbacks are captured,
controls become hidden/inert or a lane is replaced; they do not manufacture a
complete telemetry population.

The presentation uses two real labelled regions, shared native Tail controls and
one shared inspector. Responsive lane layout and bounded scrollports are kept in
the paired composition stylesheet. This source review is not a physical
assistive-technology audit or a claim that desktop/mobile screenshots were
independently inspected.

The reviewer independently ran four focused files covering paired planning,
Tail owner guards, Activity filters and Activity view contracts: all passed in
**0.332s**, with no skips. The final follow-up changes above were inspected in
source, without an additional independent live rerun.

The implementation owner subsequently reports that the final real OTLP/fault/
retained-return journey, Bombadil campaign and native observed-trace gate passed
in **57.2s**. That report includes 19 observed steps, seven main Tail connections,
and a **409-snapshot** actor completing its exact two-connection path with zero
forbidden reads and retained focus. The owner also reports **1,870 UI tests**
passing in **28.667s**, and the older single-view/late-save regression passing in
**6.4s**. These are owner-reported execution results, not independently rerun
claims by this reviewer; the exact receipts and limitations remain in validation.
