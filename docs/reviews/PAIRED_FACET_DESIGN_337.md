Status: final source and refreshed native viewport frames accepted.

## Task and scope

Investigators can narrow a change by route/tenant without discarding their pair.
This composes the existing facet with fresh fixed-query count comparisons only;
frozen captures, temporary set relations and other measure kinds stay excluded.

Reuse the existing passive facet, qualified declaration, counted-value lookup,
selection tray and Run. No new filter language, acquisition owner or toolbar.

## Minimal interaction

- Keep the contributed facet beside the comparison. Label its basis **Selected
  window values** beside its counts/read action; the baseline is not implied.
  Retain the qualified field and full applied-scope denominator/read details.
- Reuse Include/Exclude, local Find, Undo and Clear. Missing key, Present empty
  string and literal strings remain distinct; literal text is never a selector.
- A pending common selection clearly targets **Both windows**. Prefer one primary
  **Filter both windows** action that stages the revised comparison. The existing
  child Run then explicitly reads both revised fixed questions. Do not leave an
  ambiguous Apply button that reads immediately while describing staging as local.
- Omit unsupported selected-versus-current/Rest commands in this pair context.
  Do not add disabled alternatives or repeat the same scope paragraph per control.
- Keep the supplied pair unchanged while selections are pending. A staged child
  identifies the common filter and both original windows; its paused parent and
  Back path remain discoverable. Returning restores the pair, local facet/tray
  state, comparison Find/order and the originating action's focus.

## Meaning of the common filter

Conjoin one typed delta with both complete original ASTs, retaining UTC bounds,
policy and grouping. Both windows means a common restriction, not identical
scopes. Validate both candidates first; one refusal changes neither.

The values/counts initially come only from Selected window and include that
question's own applied field filters. They are neither self-excluding facets nor
loaded-row totals, and cannot prove a category is absent in the other operand.
Do not style this single count list as a two-sided category comparison; that is
338 with separately acquired witnesses and coverage semantics.

Save/export/reopen preserves definitions, not observations or pending choices.
Removing a control never removes applied filters. Replaced-scope callbacks and
detached/reconnected old controls must lose authority.

## Implementation edge decisions

Generic attribute Include/Exclude gestures may expose fields other than the
paired control's declared field. Refuse that unsupported gesture before changing
selection/history or pausing owners; retain existing valid choices and explain
which qualified facet field can filter both windows through the existing live
status. Offer changing the facet field in View settings, not an invalid tray or
silently filtering one side. The strict common-filter planner remains unchanged.

Nested filtering followed by group inspection must show only the current Back
control. Hide an enclosing child header while its deeper child is active, then
restore it on return. Inert duplicate Back buttons are not acceptable navigation;
selectors or screenshot crops must not disguise them.

## Native acceptance

1. Start from ordinary OTel logs/spans and a fresh previous/fixed-window pair.
   Add/reuse one eligible categorical facet without removing the comparison.
2. Read values explicitly. Show Selected window basis and a genuine full-scope
   count exceeding the loaded row buffer. Rendering/opening alone reads nothing.
3. Include and exclude typed categories, including missing/empty cases. Pending
   actions/undo/clear perform zero reads and do not mutate the supplied pair.
4. Stage Filter both windows. Inspect both exact queries and preserved differing
   original predicates/policy/windows; Run acquires the revised pair explicitly.
5. Inspect a changed group's records, return to the same pair/facet/Find/focus,
   then Save/export/reopen the same declaration with no opening telemetry read.
6. At desktop and narrow widths, inspect the initial viewport without artificial
   scrolling or a cropped screenshot presented as whole-page density evidence.

Generated checks cover atomic refusal, OR/budgets and missing/empty semantics;
native/actor checks own actual membership, controls, focus and completion.
Screenshots establish neither completeness nor causality.

## Final source acceptance

Accepted selected-only basis, one staging action, five existing roles, records
child+facet and current-only Back. Other-field rejection precedes mutation;
shared callbacks propagate false and inspectors honestly report Not staged.

Pending Both-windows choices now disable the parent Run consistently through
render, scope/record refresh and retained-parent restoration. Its tooltip directs
the investigator to Filter both windows or clear the choices. The retained Run
handler independently refuses before clearing views or issuing reads; clearing
choices restores ordinary Run. This resolves the prior source finding without
adding another command or changing ordinary single-population facet behavior.
Final native checks pass for both signals, including direct invocation of the
retained handler and clear-to-reenable behavior. The refreshed pending frame
visibly confirms disabled Run and Use fresh, with Filter both windows remaining
the primary continuation.
