## Product purpose and planning judgment

Keep the core: **observe now → isolate a population → follow supporting signals →
keep or reuse the understanding**. An ordinary OTel producer should not need a Goo
manifest, source annotation or optional database to begin useful exploration.
Keep compact passive components and concrete execution owners. Preserve exact
values, qualified identity, meaningful units/grain, independent clocks and honest
unknown/coverage states. These are the reasons for the architecture, not a reason
to expose every receipt, hash or intermediate owner to the user.

The complete normal 243 task now works through visible Close trace inspector →
Return to paused activity. Its first attempt clicked an occluded background return
control; that is a drawer/parent coherence seam, not a proven total pointer dead
end. The task uses three tail connections, two explicit trace/log context reads,
one fixed analysis and one fresh capture; find/reopen add no telemetry read.
Its saved artifact is the fixed original population, not an implicit archive of
all supporting context visited along the way. Preserve that distinction.

The new indexability reproduction is the first correction. After that, close the
already accepted text/capacity defects in finite cuts. Product work should then
address ordinary-data adoption and the meaning of keeping an observation, while
small return/masthead fixes continue. Comparison support and recurring trace reuse
remain useful, with narrower scope than older proposal wording suggests.

## Proposed ordered implementation cuts

These are outcome-sized proposals. Source-independent cuts can overlap, but each
gets its own review, focused acceptance and commit. They are not ten equally urgent
P0s or permission to stop product work for indefinite cleanup.

### C0 — Accepted captures must remain indexable/recoverable

**First, reproduced current behavior.** Go/architecture report an actual-handler
request of 12,728 bytes accepted by `POST /captures` (201), whose full receipt becomes
65,557 bytes. It exceeds the 64 KiB derived entry limit. Search is 503, exact-ID reopen
is 200, and rebuild returns zero/error. This is a normal accepted-input/publication
contract gap; the advertised recovery cannot repair that capture. It is distinct
from the deliberate metadata-only integrity boundary.

Prefer a bounded family-specific catalog summary projection: only ID, title,
capture time, kind/display subtype and checked declared scope needed by find/order.
Keep the full immutable question/receipt on exact reopen. Reuse the existing scope
primitive; do not mine arbitrary selectors for service meaning. An alternative
pre-admission contract must reject before source work/commit and also resolve
already accepted captures; merely stopping future writes does not fix recovery.
Do not return failed-save after immutable commit, silently skip a capture, delete
it, raise limits without a derived bound, or read all payload bodies during search.

Acceptance: the reproducer can be found/reopened and rebuilt, or is explicitly
refused before commit under a supported admission policy; all existing accepted
captures have an actual recovery path. Original payload bytes/IDs remain intact.
Test escaping/normalization expansion near the boundary, every capture family,
metadata write failure after commit, stale/missing metadata, exact-ID fallback,
query-bound pagination and schema/browser adapters. Keep the documented listing
versus reopen integrity split and aggregate byte/entry budgets truthful.

### C1 — Finish the prepared-text domain correction (I1)

**Reproduced public Go input defect.** Distinct invalid labels 0xff/0xfe still produce
one group/count 2 with nil error; valid U+FFFD/lambda remain distinct. New Go review
also finds malformed authored predicates/enums accepted. Reject malformed accepted
text instead of normalizing it through JSON replacement.

Validate the selected evaluation before population filtering/grouping/subject-key
construction, and validate authored string literals/enums in the same domain.
Preserve valid Unicode/empty values, valid output/IDs and the established visibility
of other evaluations. Direct external-consumer and property/parity controls should
cover invalid dimensions/subjects/literals, valid U+FFFD and excluded facts. No
universal digest/type hierarchy or new user-facing generic machinery is needed.

### C2 — Make native package publication/catalog capacity coherent (I2)

**Upgrade from source-confirmed to endpoint-reproduced.** Root’s owned generic
runtime accepts 257 distinct native publications (all 201); GET catalog becomes 400
(scan limit); duplicate retry still returns 201. Existing files are retained.

Choose and document one finite contract: publication admission consistent with the
reader, or bounded paged browse plus exact-revision resolution. Separate logical
revisions from physical scan accounting, including built-in/saved aliases. A bare
limit increase or racy count-before-publish is not sufficient. A prerelease API
cutover is negotiable, but a generic all-store repository/index redesign is not
required by this defect.

Acceptance: boundary, built-ins plus saved entries, aliases, duplicate/corrupt
winners, concurrent publications and already-over-limit directories. Preserve
existing bytes/IDs and explicit corruption refusal; no user-data deletion to make
the test green. New authoring/revision UX should not expand before this contract
is resolved. P4 uses a different store, so this is a release/order gate, not an
invented hard technical dependency between the two implementations.

### U0 — Make child exit restore the actual parent

The trace exit is a bounded coherence/focus cut, independent of C1/C2 once its
contract is chosen. Do not lift background controls over a deliberately full-screen
trace by globally changing z-index. Give Activity-origin context one visible
parent-aware exit/return; fixed-question origin returns to that question. Choose
honest drawer/modal semantics and do not leave occluded controls in normal keyboard
traversal. Keep passive inspector updates passive.

Acceptance: ordinary pointer X, Escape, keyboard and return at 320/390/700 px and
desktop restore visible opener, held records/selection and original scope, with no
resume/read. Keep the normal close→return integration path as well as the direct
parent intent; do not bless forced clicks through overlays.

### A0 — Choose and implement a supported no-environment adoption path

Product/source review confirms current record/native queries require an explicit
named environment, although OTel need not report that optional attribute. This is
more fundamental to general adoption than another default dashboard profile.

Prefer explicit unreported-environment selection for existing ingested data,
alongside bounded scope discovery/diagnostics and collector guidance. Decide
missing, present-empty, current/legacy key and conflicting-key semantics before
changing readers. No magic environment string, wildcard, implicit broadening or
claim that an empty scoped read proves an empty source. Collector enrichment alone
cannot expose historical data already stored without the label.

Acceptance: ordinary SDK fixture without environment can be diagnosed/deliberately
selected; named scope stays isolated; every supported service/native/record
continuation preserves the checked scope or states its unsupported boundary.
Preserve old saved named questions; avoid adding a new reusable trace definition
format before this scope decision is understood.

### S0 — Separate keeping observations from interpretation

Choose baseline versus optional exact bookmarking explicitly. Product recommends
baseline exact observed keep/reopen with optional tags/notes afterward, reusing
server-attested membership and existing retry/custody contracts through a bounded
local adapter. This is not permission to accept browser records as authoritative,
to make XTDB mandatory or to relabel a fresh fixed-question capture as the original
selection. If the capability remains optional, disclose that before selection and
name the reread alternative accurately.

Keep observed items, save a question, capture a fixed result and save an
investigation have different effects/destinations. Express them plainly in the
current surfaces; do not collapse their data models into a generic Save operation.
A bookmark without interpretation is not a reviewed classifier label or negative
training example. Preserve later training goals without starting an exporter now.

Acceptance: keep one observed item without guessing a label; expired/unavailable
membership is actionable; duplicate/uncertain retry is stable; no silent reread.
If this work reuses snapshot publication, first resolve the relevant lock/lifetime
seam rather than assuming the current bank is a universal persistence service.

### U1 — Consolidate reopened-capture presentation

The product review identifies repeated count/scope/evidence summaries before a
single saved record. Reuse existing passive evidence-summary/record components:
one compact type/scope/window/capture-time/state/count masthead and one source-effect
statement. Keep raw receipt/basis and detailed caveats in disclosures. Do not hide
unknown coverage or confuse capture clock with event window.

Acceptance uses the same one-row/long captures before/after on desktop/mobile,
record reachability and realistic keyboard tasks, not only DOM/control counts.
This can accompany adoption/preservation decisions without delaying them for a
whole stylesheet rewrite.

## Enablers and refactor boundaries

- Select a required, disposable generic-OTel browser task tier around the complete
  loop; preserve the current root/Node/API fast gate and strict named model verdicts.
  Do not require every historical actor/model/woven campaign on every edit or hide
  missing tools with a successful skip. Tool/context prerequisites must be explicit.
- Revisit snapshot publication lock isolation and detached compiled-plan ownership
  as named reliability/API cuts. Preserve reservation time, idempotency and uncertain
  publication. A copied public plan snapshot should not require users to understand
  nested-map aliasing. Neither finding authorizes universal store/hash cleanup.
- Plot navigation and updates should use one bounded keyed enter/arrows/select/leave convention
  for a real dense widget, preserving exact points and unknown intervals. The issue
  is practical keyboard/touch use, not a module-count or asserted certification.
  Frontend independently reproduced lost focus on an identical timeline data update
  and a closed latency disclosure after identical summary assignment. Retain keyed
  focus/selection/disclosure state, define removal fallback and never acquire focus
  from passive arrivals. Include a real owner refresh before claiming SSE readiness.
- Correct the small method-specific OpenAPI effect mismatch: legacy `GET /captures`
  lists saved data but currently inherits POST publication effects. Pin GET/POST
  effects separately; a POST counter is not a universal telemetry-read oracle.
- Reuse source-policy conformance tests before merging differing adapters. Share
  demonstrated mechanics, not semantic outcome algebra or row interpretation.
- Deployed asset identity and evidence retention need a small explicit contract;
  current byte checks are useful, but a passed unit count is not fresh provisioning,
  full browser/native coverage or an artifact-size quota. Require a build/input
  manifest for the selected tier and reject a stale binary with unchanged API shape.
  Keep model safety conformance separate from complete-task evidence: the catalog
  model accepts a save-only conforming prefix. Observe terminal reopen identity,
  completed actions and settled collection independently, rejecting wrong scope,
  wrong artifact and extra local-return reads. Reuse the pinned gotogether pilot
  only where useful; do not migrate all suites or treat a lost tail as success.
- New generics/stdlib/ESM work earns priority through a measured or reproduced
  consumer benefit. Existing Go 1.27 baseline, native ESM, checked references and
  explicit runtimes remain closed. Prefer internal improvements and simple public
  APIs; negotiate a prerelease cutover when it actually improves use.

expressions/DataFusion/CEL/KCL execution, mandatory temporal storage, classifier
