# Product checkpoint after source-demand work — 314

Status: bounded product recommendation, not implemented follow-on work.
Read with [313 actual-frame review](ACTIVE_CANVAS_DESIGN_313.md),
[314 source-demand review](SOURCE_DEMAND_ARCHITECTURE_314.md) and the active
[November roadmap](../ROADMAP_2026_11_03.md).

## Judgment

314 removes real unnecessary work: a supported fixed baseline now acquires its
needed aggregate through two statements instead of the former four, while the
selected view retains records and its independent basis. That is a useful measured
reduction, not proof the whole interface is faster or easier. It does not resolve
the visible obstacle left by 313: sparse controls/context still occupy the space
where a responder expects relevant data.

Keep the product loop — see now, isolate, follow signals, preserve/reuse — ahead
of another chart/profile family or generic model rewrite. The next finite outcome
should make the existing useful controls fit that loop. Then close a genuine
scope-navigation gap, rather than indefinitely polish the same widget.

## Review evidence

Reviewed final actual 313 desktop/narrow/restored-root frames, current shared facet
styles and component/source boundaries, and the delivered 314 measurement/aggregate
contract. A fresh read-only independent Chromium session against running 8088 on
2026-11-03 confirmed current Activity and service entry. No stored view, capture,
Keep, annotation or other durable write was submitted.

The current Activity still puts live records first. Pausing and opening a service
pill exposes **Only this service**; it has no direct service-context handoff.
Choosing Services & resources opens a discovery form with Environment and Discover
services, rather than carrying the observed record's checked environment/window.
This is direct current DOM evidence, not a hypothetical missing capability.

The final 313 desktop frame shows two method values inside roughly 430px of facet
header/actions/counts/Find/row/card space. Its chart starts below that block. The
390px trace-child frame uses roughly 400px on outer Activity/service/trail context
before the local child; the useful record data lies below the first viewport.
313 correctly removed the dormant root editor and duplicate inner child exit;
it deliberately did not resolve those remaining presentation costs.

## 1. Next: compact the shared facet and active context around useful data

Deliver one shared-component density cut across the actual contributed HTTP view
and nested incident canvas. Reduce value-row/action spacing, combine repeated
facet facts into one readable context line with detailed receipts behind the
existing disclosure, and remove redundant nested card chrome. Preserve the
qualified field, applied-scope meaning, full count versus page facts, independent
read/unknown coverage and explicit Read values. Do not hide those facts simply to
win a height measurement.

Keep Include/Exclude targets usable by pointer/keyboard/touch, visible focus,
loaded-value scrolling and logical focus through updates. Local Find should
announce its number of loaded matches, including zero, independently of the full
population count. This is a presentation refinement, not another predicate or
query execution path. No source request may be added by mount, Find or layout.

For contextual returns, compact their presentation without conflating owners.
Retain the existing exact parent/service/paused-Activity targets until a checked
ancestry presentation contract supports coalescing. Reducing duplicate labels or
layout height is useful; hiding the only valid return or changing Back semantics
is not. Preserve held parents, scroll/focus and zero-I/O navigation.

Suggested acceptance targets are **proposals**, not delivered measurements:
a normal two-short-value facet should fit about 220px instead of ~430px, and
outer mixed-origin context should aim for roughly half its current narrow height
where essential ancestry can remain understandable. Define the data-first goal
per task: relevant facet values or the selected visualization should be reachable
in the first viewport; requiring all charts and records simultaneously at 390px
is not a useful constraint. Compare before/after actual 1280×900 and 390×844
frames, with keyboard and no-extra-read assertions.

Measure a legitimate long-value/high-cardinality case while touching the shared
surface. If it demonstrates excessive bytes or repeated DOM rebuilding, apply one
shared property/attribute input budget and bounded update policy in the same
finite boundary. Do not silently truncate categories while claiming exhaustive
counts, and do not schedule an independent performance framework merely because
there is a 1,000-item cap. Prioritize demonstrated task failure over speculative
optimization.

## 2. Then: continue from an Activity service into its observed context

The next stronger product gap is continuity between “this service is interesting
now” and the service overview/default/contributed view. Today the user changes
navigation, re-enters environment and discovers a fresh window. That interrupts
the incident and can compare different telemetry without an obvious decision.

Design one contextual **Open service** continuation from the existing service pill
or record inspector, using its checked identity/environment policy and a deliberate
fixed observed window. Reuse the existing service owner/dashboard/template flow;
no new destination or background inventory preload is needed. Keep the paused
Activity as the return parent and make source execution explicit under that
owner's existing policy.

This is not permission to copy a log-body filter into an HTTP-span question or
silently drop it under an exact-scope claim. Define portable identity/context
fields, namespace missing/empty/named cases, typed environment support and the
window separately from source-specific predicates. If the destination cannot
honor a field/policy, refuse or explain the narrower context handoff accurately.
Do not invent wildcard environment semantics or claim retained causal identity.

Acceptance: from a real scoped incident log/span, open its service overview with
matching checked identity/environment and explicit time context, continue into a
useful default/team view, then return to the same held Activity without reread or
resume. Include typed effective environments and ambiguous/unsupported identities.
This advances the core investigation loop more than mechanically adding another
facet family or comparison measure.

## Finite scope and deferrals

Two product items are sufficient. Keep portable YAML/CLI/catalog work, query-pair
persistence and shared windows delivered; do not build another registry or editor.
Keep production auth/source isolation, durable alarms/SLO routing and richer
training labels as distinct retained workstreams, not hidden requirements of this
density/navigation cut. Reassess after the concrete tasks above rather than
continue an unlimited chain of component polish or vendor parity research.
