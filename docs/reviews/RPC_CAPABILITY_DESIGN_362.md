# Current RPC capability parity — design 362

Status: accepted after final source, canonical native/model/actor and original-detail
actual-frame review. Existing metadata density/narrow-table limits remain explicit.

## Cohesive cross-surface meaning

Services already names the current server-span lens **Current RPC**, separate from
Legacy RPC. Measurements should recognize `rpc.server.call.duration` through its
existing curated capability presentation, with a concise **Current RPC duration
candidate** title and the same pinned OpenTelemetry v1.45.0 convention used in357.
Do not add a panel, chooser, browser convention planner or another metric binding.
The existing exact instrument/stream discovery, Inspect and explicit Run remain
the interaction path.

The current instrument shape is Histogram in seconds. Legacy
`rpc.server.duration` in milliseconds remains a separate literal instrument;
neither the shared RPC wording nor a mismatched unit authorizes conversion,
schema migration or fusion. Wrong kind/unit must produce a specific existing
capability hint while preserving the ordinary generic binding when that binding
is eligible. Metadata recognition is not conformance, valid histogram intervals,
coverage, protocol error rate or unique request throughput.

## Attributes and uncertainty

Show bounded per-stream coverage through the existing matrix, including
`rpc.system.name` and `rpc.method`. A key observed somewhere is not proof that it
is present on the stream being inspected. Missing and empty remain separate from
a nonempty reported value. `rpc.method` is conditional; missing/empty values and
literal `_OTHER` do not by themselves make a current RPC instrument ineligible.
Do not invent a wrong-value diagnosis from presence-only metadata. Where the
pinned convention constrains a value, state that values remain unverified until
an actual checked witness/evaluation supports the claim.

The card must retain the existing not-run verification meaning. Shape match,
generic execution eligibility and convention conformance are distinct facts.
Neither schema URL nor matching metric name is a validation badge. Observed
native streams remain separated by exact identity, temporality and interval;
no fleet percentile or merged delta/cumulative series is implied.

## Genuine journey and frame acceptance

Discover the same genuinely reported Current RPC instrument already usable from
Services. Inspect its curated candidate in Measurements without a new query
surface, then explicitly Run its exact stream and show seconds-based duration
observations with normal interval/coverage disclosure. Include missing/empty
conditional method evidence, a reported `_OTHER`, wrong-unit/kind metadata and
an otherwise eligible generic fallback in focused checks. Verify no automatic
source execution on card/metadata opening and no legacy/current stream merging.

Actual desktop/narrow frames should show the existing candidate title, shape,
not-run meaning and readable coverage alongside the existing action; a result
frame should establish successful explicit exact-stream execution. Do not claim
that a metadata frame proves numerical validity, or that a task-scrolled frame
establishes first-entry density. Keep hints concise and avoid repeating the
entire convention in prose above actual instrument information.

## Frozen source acceptance

The implemented exact-current branch uses the shared Histogram/seconds shape,
pinned ruleset and existing candidate card. Conditional method/status coverage
does not disable Run; missing/empty/_OTHER remain literal. Presence does not certify
values, schema migration, a universal failure policy or a span-to-metric join.
Wrong shape explicitly retains an otherwise eligible generic binding without
conversion/legacy alias. Generic eligibility and not-run verification remain
separate from shape recognition. This source contract is accepted. Native/model checks and actual-frame
acceptance are complete, as recorded below and in validation.
