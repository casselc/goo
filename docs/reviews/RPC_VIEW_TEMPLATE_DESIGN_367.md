# Current RPC reusable view — design367

Status: accepted after frozen source, canonical native/model/actor and original-detail
actual-frame review. Existing template/editor density limits remain explicit.

## Extend the existing useful handoff

HTTP/database already connect service evidence to ordinary aggregate-and-records
compositions through `view-template-handoff`. Add the same natural **Customize**
entry for Current RPC server spans. Suggested visible labels are **Current RPC
server view** and **OTel current RPC server spans**; root closes exact wire profile,
family and preset identity. Keep current/legacy convention meaning explicit rather
than calling this a generic RPC operation identity.

The profile requires exact nonempty service, reported Server kind and nonempty
current `rpc.system.name`. `rpc.method` is conditional: missing, empty and literal
`_OTHER` groups remain distinct and eligible. A method group can span reported RPC
systems within its service/namespace; it is not a globally unique operation or
request. Legacy `rpc.system`-only and Client-role questions must refuse this checked
profile, not be silently upgraded or broadened. Generic ordinary views remain
available under their existing contract.

## Reuse presentation without importing specimen evidence

Use existing Customize→local composition editor→Save reusable template→Inspect
compatibility→local Apply/stage→explicit Run. Saved/imported definitions are
configuration, not an observed result. The donor binds destination grouping and
supported presentation/measure, never its service, environment, namespace, fixed
window, held result or source-read clock. Preserve the entire destination typed
question and exact role/current-key predicates. Do not reconstruct typed policy
from labels or allow wrong-profile preview to read source.

Keep existing ordinary count/duration aggregate plus records/timeline/comparison
compatibility rules. No native histogram template arm, complete-trace statistics,
protocol-failure policy or mean-latency explanation is introduced. Existing passive
components and server checked expansion remain the authority; no browser-side
convention planner or universal registry.

service-library handoff. Genuine Current RPC source with reported Server role and
current system key should Customize and save/reopen a reusable method view, then
apply to a different exact service/namespace/policy/window. Confirm source0 for
metadata/Inspect/Apply/staging and explicit count/record reads only after Run; Save
and reopen retain whole question and presentation truth.

Include missing/empty/_OTHER method categories, legacy-only keys, wrong role,
wrong-profile donor, specialized numeric/native shapes and destination draft errors.
Refusal keeps destination scope and usable existing controls, with no autoRun or
coercion. Child/Back returns to the held parent and current opener; old callbacks
cannot apply or read after replacement. Actual desktop/narrow frames should show
Current RPC profile, exact destination scope, compatibility decision and real
applied categories. Task-scrolled frames do not prove fresh-entry density.
