# Saved exemplar review — 380

Read-only architecture/usability review and frozen-source rereview found no
remaining blockers. Runtime and generated checks are recorded separately in
[validation](../../VALIDATION.md).

The existing Saved owner already holds immutable receipt/result data and returns
through the application-owned fixed-question flow. Extending that owner is enough;
a new navigation manager or a fake live source adapter would add conflicting
authority. An explicit Saved-only capability enables reported references, while
shared held admission defaults to interval-only for service widgets.

Admission reconstructs the complete reported-exemplar plan from the frozen raw
source export and sample ordinal, checks unique held stream identity and compares
all proposed fields against the retained question, basis and read clock. It does
not substitute a numeric interval for source export occurrence. A reported sample
can remain meaningful when the distribution is unknown, but missing, ambiguous
or changed metadata cannot grant navigation.

Live exemplar links intentionally pause until a new measurement Run; Saved links
must instead resume locally on Back. The existing Saved action lease now rebinds
ordinary and auxiliary clicks without rerendering, changing custody or rereading
source data. Hidden, inert, detached, foreign-owner and stale callbacks prevent
native link navigation. Inactive timeline selections cannot change held inspector
state during departure. The return citation now includes capture identity and the
full export/sample occurrence, with an honest reported-association notice.

Service widgets remain interval-only: merely using the saved-style renderer is
not exemplar navigation authority. This boundary is intentional scope for 380,
not a claim that every native surface can follow reported references.
