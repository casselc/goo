# Checked environment policy through a record service journey — design 318

Status: bounded implementation source and all three actual browser frames accepted.
Read with [316 handoff](SERVICE_HANDOFF_DESIGN_316.md),
[record selector meaning](../RECORD_SELECTOR_API.md) and
[317 product priorities](WHOLE_PRODUCT_DESIGN_317.md).

## Useful implementation outcome

An ordinary OTel service using a legacy environment key, an explicitly empty
label or no environment label can move from Activity to a useful record-based
service overview and Customize without weakening its checked selection policy.
Deliver an actual end-to-end record-family task, not another contract-only review
or a string fallback. Keep the existing stage → explicit read → Customize → paused
return flow; no additional wizard, picker or catalog is needed.

The minimum meaningful slice is an effective-named legacy-SDK service with real
span/log observations through the existing record dashboard and contributed view.
Include effective empty/unreported modes when the same checked record scope /
source admission can support them end to end. Do not claim every native/entity
family becomes selector-aware because one record journey works.

## Visible scope and exact selection

Reuse the existing checked environment label in staged service context, current
service scope, Customize and origin return. A named effective scope should read
like **Environment “prod” · current/legacy precedence**. Empty is an explicit
empty label, not a blank input or Any environment. Unreported means neither key
was reported; it is not null/unknown metadata. Keep the policy visible so matching
name text cannot hide the difference from current-only.

Current-key presence wins even when empty or conflicting. Legacy fallback applies
only when the current key is absent; do not union aliases, prefer a nonempty value
or normalize both into a single unchecked name. The UI need not explain this on
every row; the policy label and one existing scope/read-facts location are enough.
Raw resource maps and checked source admission establish it, not presentation.

Preserve service name, resource namespace missing/empty/named identity, exact
original occurrence window and all relevant checked scope fields. Unknown resource
identity remains a refusal. Log-attribute conflicts must not replace resource
identity. Existing Activity filters remain explicitly not carried to the broader
service context; do not advertise exact original log/span predicates.

## Stage, read and Customize

Open service stages the full checked intent with no discovery/dashboard requests.
Read service overview explicitly acquires the supported record inventory and
record dashboard under that same policy/window. Backend plans and browser scope
admission must agree; a returned name-only question is not equivalent to an
effective selector even if counts happen to match.

The overview remains useful: captured record counts, recorded Error/duration/
route groups where the existing profile supports them, records and trace actions
retain their units and uncertainty. HTTP defaults still require reported Server
and current nonempty method; environment fallback does not authorize HTTP
semantic-convention alias unions or new outcome policies. A no-data record result
is not proof of service health or completeness.

Customize expands checked question/presentation only, preserving the full selector,
fixed bounds, service and namespace. Its explicit Run and facet Read values use
the existing typed record owners. Save/export/reopen retain policy; no manifest
or instrumentation annotation is required. Return keeps the actual originating
service/Activity lease and does not start a new discovery window.

## Unsupported subpanels are unavailable, not empty

Native instruments, entity/deployment metadata, annotations or another family
must not receive an empty legacy environment string, a current-only projection
or a broad query when they cannot honor the policy. Before source execution,
withhold those requests and present **Unavailable for this environment policy**
with the actual family limitation in the existing subpanel/prerequisite area.
Do not show zero metrics, Not observed, an empty instrument picker or a global
Overview failed state for deliberately unacquired data.

Keep the supported record overview usable. One concise availability fact near
the relevant section is sufficient; avoid a warning checklist above the data.
No disabled annotation Save or native Read command may accidentally publish /
execute under a guessed identity. Existing manual discovery may remain available
as a separate explicitly chosen scope, never a silent fallback.

## Named return and source lifecycle

Back to paused Activity and Back to service preserve their existing owners,
checked origin label/window, held records, selection, scroll and visible opener.
They read nothing and do not resume tails. Changing policy, service, window or
visit retires pending inventory/dashboard responses and old actions. Preserve
actual request cancellation through the current executor, not only late-response
suppression. No new global context/session owner is needed.

## Finite acceptance

Use real OTel records with a legacy-only effective-named environment plus current /
legacy conflicts. From the actual Activity service menu, stage, read a useful
record overview, Customize/Run, inspect a trace and return. Prove policy/window /
namespace continuity, zero-I/O staging/returns and no unsupported family requests.
Counts must distinguish current-empty precedence and conflicting current labels
from eligible legacy fallback; do not substitute a perfect name-only fixture.

For accepted empty/unreported modes, verify the same task or state explicitly
which cases are pure/API/property coverage rather than a native matrix. Invalid
or unsupported identities/policies must refuse with a readable reason, not become
Any environment. Review actual staged/record-overview/contributed-view frames for
policy labels, record units/uncertainty and honest unavailable subpanels. Source /
model verification establishes request effects and completion separately.

Do not expand this into every native family, automatic alias registry, service
suite parity or another general query language. A complete useful record-service
journey with honest remaining capability limits is the deliverable.


## Final source and actual-frame acceptance

The implementation delivers checked record-service scopes for effective named,
empty and unreported environments through the existing stage/read/dashboard/
Customize owners. It preserves current-key precedence and the original fixed
window rather than projecting to a legacy name string. Native/entity/annotation
and scalar saved-Activity-view panels that cannot honor the policy withhold their
requests and state their actual limitation. Their concise separate family messages
are honest capability facts, not missing-data or zero signals; no additional
styling/consolidation is required to accept this cut.

All three actual frames are accepted. The
[effective service records](../journeys/screenshots/318-effective-service-records.png)
show the route split **three current / two legacy** captured server spans, with
recorded error/support and native instruments explicitly unavailable for this
policy. That warning does not claim no metrics were emitted. The
[narrow unreported overview](../journeys/screenshots/318-unreported-service-records.png)
shows **seven** server-span records, 0/7 recorded Error, unset/unknown support,
record-based rate and duration, alongside one captured log record. It does not
reinterpret unreported environment as unknown health or a native metric value.
The [customized view](../journeys/screenshots/318-effective-customized-view.png)
visibly retains the effective current/legacy policy and original UTC window, with
Back to service, paused-Activity return and the ordinary method-facet/chart/view
controls. Read values stays explicit.

The source and native verification establish policy membership beyond these
cropped frames: the final journey reports actual current-only positive, effective
named **five**, empty **five**, and unreported **seven** cohorts, with metric
presence **two / one / one** in the typed cases to prove unsupported native panels
are not merely empty. Identity/window propagation, explicit acquisition and
Customize/paused return remain the observed task contract. Pure/property checks
cover further policy/identity counterexamples; do not describe that as a larger
native matrix. Final execution timing/campaign verdict remains in validation.

The record units, unknown coverage and independent-read meaning remain visible.
No source UX or visual blocker remains; no new product features, source edits or
CSS expansion were requested by the final design review.
