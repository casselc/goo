# Typed error-triage continuation — design 370

Status: accepted after final source, genuine desktop/narrow frames and canonical
native/model/actor completion. Scope is triage only; distribution admission remains
separate work. No new wizard, renderer or error taxonomy is introduced.

## Accepted user flow

A user scopes Activity, opens Errors & exceptions and chooses Inspect group or
Compare within service from actual service/type evidence. Existing question links
stage the child; only explicit Run reads telemetry. Back restores the held triage
parent and its current opener, scroll/disclosures and source clocks without rerun.

The whole typed environment policy, namespace/resource predicates, signal, fixed
window and original recorded-error rule survive. Exact service/type predicates add
to that parent instead of replacing its scope. Missing, present-empty and literal
sentinel-like values stay distinct. Derived exception-type membership follows the
existing checked field semantics, not a browser-invented summary.

Compare within service narrows the same error-evidence population to the chosen
service and groups by type. It does not compare errors against healthy traffic,
establish an error rate, identify a unique issue or prove causal exceptions.
Counts remain matching records from independent source reads.

## Source and ownership review

The unnecessary typed-selector ban is removed only for triage links. Builders and
question protocol remain authoritative. Actions require a coherent observed/no-data
result, an actual admitted group, the held result and applied question generation.
Changed-read, dirty, unsupported/read-only or stale origins cannot bypass their
existing guards or fabricate zero groups.

A dedicated triage-group flag and renewed link leases support held Back without
broadly rearming the separate scope/action context. Suspended, detached, hidden or
replaced old closures cannot stage a child after the owner changes. Current links
remain usable after return. No unrelated distribution admission or new navigation
manager is included.

## Genuine runtime acceptance

The final canonical native run passed in about 2 minutes (runner 2.1 minutes),
including typed scope/member checks, detached/hidden old-source refusal, unchanged
child/source counts and narrow current-link focus/center visibility without IO.
Required observed model passed in 13.19 seconds with zero skips; negative mutations
were rejected. The positive actor recorded 688 snapshots across 13 phases in
45.151 seconds, with three reads, one SSE and zero writes/store operations.
Root reports Go, all 1,276 UI tests and 40 generated checks passed.

Those ledgers establish exact membership, staging/Back budgets and ownership;
screenshot appearance alone does not certify query equality or completeness.

## Actual frames and limits

Viewed original-detail typed-group-records, held-typed-triage, typed-triage-390 and
typed-triage-actions-390 frames. Desktop child shows current-key-only scope, fixed
bounds, two matching logs and explicit Run/Back. Parent groups visibly distinguish
IOError, present-empty and missing types, including a quoted literal service, with
Inspect group and Compare within service actions.

The first narrow frame shows readable identities; the additional horizontally
scrolled frame shows counts and usable wrapped action links. Native focus/center
checks support keyboard access. These separate crops do not show identity and
actions simultaneously: the existing horizontal table remains a mobile usability
limit, not a compact-layout claim. Frames are task-positioned, not first-entry
proof. No material typed-continuation blocker remains and no broader UI change is
required for this milestone.
