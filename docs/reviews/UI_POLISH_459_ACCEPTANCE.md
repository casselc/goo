# Shared UI polish acceptance

Independent UX, accessibility and web-standards follow-ups accepted the shared
attribute, catalog, navigation, state-marker and announcement changes. Separate
designer and UX specialists then reviewed the polished surfaces and their prose;
those proposals are consolidated in [Contextual guidance](../CONTEXTUAL_GUIDANCE.md).

Fresh 320/390/1440 frames retain readable Search/Scope controls, source-state text,
UTC values, service signal units and explicit **Not observed**. Field-qualified
Copy/menu names distinguish equal keys across namespaces. Closed mobile rows are
compact; expanded native menus remain readable and keyboard/hit-test accessible.
Long real messages can still require scrolling within the bounded inspector.

The browser checks Enter/Escape menu focus, native help Enter/Space, route-preserving
Skip on Services/Saved, a no-JavaScript skip fallback and 44px coarse-pointer
controls. Chronology has one atomic polite announcement. Actual standalone
Chromium checks verify forced-color chart marker boundaries: CanvasText contrasts
21:1 with white/black Canvas, while the existing state text remains visible.
The empty CSS pseudo-element adds no duplicate assistive-technology text.

Both Phase 2 specialists agreed to the immediate native **Local observation · not
saved** disclosure: current custody state stays visible, and its existing staging
explanation is available on demand. Actual messages, failures, source clocks,
coverage/validity states and action consequences remain product information.
A common Help panel and optional walkthroughs are proposals, not delivered UI.

The real before/after journey preserves the same 30 fixed source identities,
checks eight local zero-read interactions and refreshes final documentation frames.
The existing chronology/Bombadil/native Quint regression also passes on the same
accepted runtime. No remaining scoped blocker was reported. These checks do not
claim whole-product accessibility certification.
