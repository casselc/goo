## 2. Depth: close one broker observation contract, then decide delivery

Task: Explain a backlog using actual broker observations rather than treating
messaging process spans as queue health.

`exploration/dashboard.go` already has producer/consumer roles and explicitly
warns against that inference. `measurements/source.go` preserves full identity
and warns that consumer-group observations can repeat across workers. These are
prerequisites, not a missing generic dashboard implementation. A demo queue metric
is not sufficient to select names, units, kind or entity identity.

Do a bounded official/exporter-pinned contract first: one instrument family,
queue/vhost/resource identity, stock versus counter meaning, temporality and
repeated-observer rules, with genuine exporter-shaped input. If it closes, one
candidate/explicit exact-stream view can use current discovery/kernels. If it
does not, record the refusal/defer decision and proceed; do not hold other work
hostage or publish “broker health” from guessed conventions. This is a research
and readiness outcome until a source-backed instrument is actually selected.

## 3. Consolidation: one native-view grammar readiness boundary

Task: Save a small native histogram display choice and reuse it with an exact
compatible measurement question through the same kind-based product approach.

`ui/view-template-handoff.mjs` and `workbench/view_templates.go` deliberately
accept ordinary record compositions and refuse native/specialized questions.
Existing native passive displays and measurement packages already provide the
arithmetic and exact stream model. Merely allowing a native payload through an
ordinary record arm would lose its unit/coverage/temporality semantics.

Close a bounded separate native declaration arm before feature implementation:
one supported histogram display, complete checked measurement question, explicit
kind/shape compatibility and known/partial/unknown semantics. Reuse existing
measurement DTO/protocol admission, passive kinds and immutable view publication;
no new evaluator, WYSIWYG system, registry or universal query executor. Source-free
Stage must retain the destination's whole native scope/interval rather than donor
stream data. If a small declaration cannot cover that honestly, defer the feature
with the unresolved contract named. This is a readiness consolidation, not a
promise that all UI surfaces can already use one record schema.

## Structural and reliability lessons to carry with these cuts

366 and 369 show why source-only layout/performance claims are insufficient:
matched styled frames and trace-disabled actual event timing changed decisions.
Keep baseline source hashes and separate construction CPU, paint opportunity and
driver/source wall time. Paging changes presentation only; full population counts
and unknown-versus-zero authority remain independent.

368's host mismatch and 367's typed echo mismatch were found at actual entry
points. Keep one real owner/route schedule alongside independent membership and
integer-boundary oracles. Do not multiply fixed-script model replays that merely
follow a declared success path. Reuse mechanical fixture/transport helpers when
useful, retaining independent semantic oracles.

The new review workflow's long local module remains a readability risk when it
is next expanded, but an annotation platform or standalone formatting queue is
not the next product goal. Durable intents, bounded graph walks, selected-branch
manifests and immutable raw records are adequate for its present contract.
Tenancy/authentication, global consensus, exemplars and Databricks lowering remain
separate explicit product contracts. None follows automatically from adding
labels or a bounded native view.
