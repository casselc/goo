# Whole-product design/product checkpoint 363

Independent review after 362 acceptance. This document proposes candidates;
execution order is decided by the checkpoint reconciliation. No implementation,
new vendor survey or browser run is included.

## Product loop and delivered ground

Goo helps a user see current telemetry, scope a population, follow reported evidence,
and retain/reuse what mattered. The interface should make that loop immediate;
its grammar keeps scope, measurement, uncertainty and display meaning coherent.
Live Activity, chart selection/facets, count/share explanation, automatic service
profiles, native measurements, resource/Kubernetes views, reusable templates and
typed packages already exist. Do not recast these as missing broad categories.

360 now makes stored spans locally inspectable in Table/Waterfall,361 compares
explicit retained pages, and362 brings current RPC metadata recognition into the
existing Measurements card. Those are connections between useful surfaces, not
new query engines. Future cuts should keep this cross-product focus and the
application-owned acquisition/passive display boundary.

## Recommended finite outcomes

### Breadth: one reviewed evidence-label task

The user explicitly wants interactions to produce useful later training material.
`TRAINING_ANNOTATIONS_DESIGN.md` still marks reviewed task labels/vocabularies and
dataset export proposed; existing tags/notes are implemented foundations. Start
with one declared task over exact immutable captured record occurrences, using the
existing contextual Annotate entry rather than a separate training workspace.

A user opens a retained example, assigns a task-specific value or abstains, records
why, reviews the decision and exports a pinned manifest. Keep unlabeled, negative,
uncertain, withdrawn and disputed distinct. A set-level judgment must not silently
label each member. A saved population is a collection recipe, not ground truth for
all future matches. Export must identify original occurrence/capture and decision
revision, never silently reread the source or mutate OTel attributes.

Stop after that genuine end-to-end task and an explicit versioned export contract.
No active learner, model runtime, automatic labels, new bitemporal backend or
free-form ontology is required. Architecture must assess existing annotation
identity/review storage before adopting this as implementation work.

### Depth: retained native interval to supporting records

`KNOWN_ISSUES.md` and `NATIVE_RECORD_CONTEXT.md` describe the existing exact native
interval→record-context handoff in live Measurements; saved/native-service displays
still lack the retained handoff. A user inspecting an interesting saved histogram
interval should be able to deliberately stage the same bounded record context with
its exact resource/service/namespace/instance and nanosecond interval authority.

Reuse that existing contract where the stored result actually retains a valid
interval. Preserve the original native receipt as provenance; explicit Run obtains
new records with their own clock. Gauge points and aggregate buckets must not invent
windows. This is related context, never exemplars, contributing requests, causality
or an atomic cross-signal snapshot. Stop at one existing saved native histogram
path and its exact context/return journey; do not build a generic correlation engine.

### Consolidate: results before full evidence paperwork

Actual361 desktop provenance occupies roughly900 pixels before timing bars; narrow
is taller still. Its maintained narrow frame shows only the baseline facts, not
its timing result.358 moved plots up431px desktop/890px narrow but its selected
plots remained below the fold. These are concrete limitations, not evidence that
compactness is solved.

Measure genuine entry at1280/390 for an applied fixed result and retained pair,
then use compact independent operand headers with full clocks/limits in existing
disclosures. Keep source-read/custody/question clocks distinguishable and unknown
state visible; never hide dirty/invalid authoring or make Run automatic. Reading
and comparing the result should precede a page of exhaustive metadata. Reuse shared
evidence facts/presentation rather than another owner-specific sidebar. Acceptance
must report actual result position and keyboard access, not task-scroll crops or
only reduced control counts. Stop after these representative owners demonstrate
an improved result-first reading task with unchanged acquisition/custody.

## Candidates requiring evidence before scheduling

Metric exemplars require actual source/exporter fields and retained identity;
a histogram alone cannot supply trace IDs. One broker backlog family requires a
pinned real exporter/instrument/resource grain, not processing-span inference or
lab.queue.depth. Large paired facets retain a32k-element concern, but current
mount/search/action/Back measurement must establish a material user problem before
paging/virtualization; old five-build CPU figures do not prove current paint cost.

Do not restart delivered service/currentRPC/template/capture work, add a universal
profile registry, mandate Plotly/WYSIWYG, or schedule another chain of copy fixes.
The planner should reconcile these few outcomes with architecture readiness;362
must finish before any next delivery begins. No fresh Datadog/Honeycomb/Grafana
comparison was performed for this checkpoint.
