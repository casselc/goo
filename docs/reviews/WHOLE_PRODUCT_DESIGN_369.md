Source-grounded checkpoint proposal after 369 bounded runtime and actual search/paging

## Keep the investigation loop coherent

Current telemetry→scope/isolate→follow evidence→retain/reuse remains the product's
core. Live logs/spans, visual selection, counted facets, service/resource defaults,
error/exception triage, log patterns, numeric measures, checked templates and saved
views already exist.367 adds Current RPC role-bound reusable views;368 connects
actual service histogram intervals to explicit record investigation.369's source
candidate bounds local facet rows after repeated measured clear-search stalls;
its after-results are not yet evidence in this review.

Avoid another chain of narrow template/profile additions merely because they are
straightforward. A modern typed scope should not work at entry then disable natural
follow-up gestures; users should reuse the same checked scope across representations.
365 review-task exact-ID friction remains real but deferred, not a reason for an
annotation-platform expansion immediately after its foundation.

## Three candidate outcomes for architecture/planner reconciliation

### Breadth: finish typed error-population follow-through

Architecture identified a concrete source gate: `exploration.mjs` group actions
reject typed environment selectors before existing ErrorTriage builders, while
those pure builders already clone/validate the whole parent query. The feature is
not missing triage; it is a broken continuation in the main scope→isolate→follow
loop. Remove only proven unnecessary gates under existing protocols.

A user scopes current Activity with current/effective/unreported environment policy,
opens error evidence, selects an exact service/type group, inspects supporting
records or stages its comparison and returns to the held parent. Preserve namespace,
all predicates, fixed time, signal and recorded-error meaning; no scalar label
reconstruction or coercion into protocol failure. Stage source-free, Run explicitly,
and reject unsupported exact-edge/specialized origins rather than dropping them.
Stop after these existing gestures work with genuine typed data and wrong-scope/
late-owner negative checks. No new triage engine, issue tracker or error taxonomy.

### Depth: make one native view authoring seam explicit

General-purpose observability needs team-authored views of native evidence, not
only stock shipped cards. Existing reusable templates deliberately support ordinary
record/aggregate shapes; native histograms are not an extra profile switch. Begin
a strict readiness contract for one exact-stream histogram interval display using
the existing data/uncertainty model and passive renderer.

Close complete-input versus unknown coverage, unit/temporality/stream identity,
interval versus aggregate bucket, destination binding and explicit Run before any
UI implementation. A template cannot import specimen scope or create fleet percentiles.
If this cannot fit the checked grammar without a broad new query/renderer platform,
defer implementation explicitly and select a smaller validated outcome. Do not
market a count-template alias as native authoring. This is a candidate gate, not
permission for a WYSIWYG project or universal registry.

### Consolidate: unify typed continuation admission at real boundaries

After the first typed triage path, audit its sibling distribution/population entry
checks against existing shared question protocols. Architecture found another
explicit typed ban in distributions.openPopulation. Prefer one checked whole-query
admission path for existing record continuations, with explicit capability refusal,
over local scalar-only conditionals that drift from backend support.

Keep this finite: representative Activity→triage and distribution→population child/
Back paths, exact query equality, no hidden reads and current focus/owner proof.
Do not sweep unrelated service deploy/annotation entity gates whose scalar scope
may have genuine data contracts. No generic scope manager or router replacement.
The planner may combine this with breadth if the implementation is inseparable,
then choose another material consolidation rather than inventing duplicate work.

## Alternative broader feature requires real source first

A broker backlog/age family is useful breadth, but only a pinned actual exporter,
metric/resource grain, temporality/unit and fixture can establish queue depth/age.
Research can produce an accept/defer contract; processing durations cannot stand
in for broker health. Exemplars likewise need actual source fields and identity,
not inferred contributors. Alerts/SLO scheduling/notifications require their own
state/delivery contract and are not a small query-preview toggle.

Do not reopen delivered headers, service defaults, reviewed labels, RPC templates
or native context. Keep actual screenshot limitations and measured performance
claims separate from source readiness. Final 369 acceptance and planner/architecture
reconciliation must precede any next feature sequence.
