# Whole-product design/product checkpoint 375

Proposal only while 375 completes actual geometry/interaction acceptance. No next
sequence is adopted by this review; no vendor scan, tests or production edits.

## What the product now does

Goo's loop is live telemetry → scope/isolate → follow evidence → preserve/reuse.
Typed triage/distribution continuation, service native interval context, native
Histogram/Table declarations and discoverable native displays connect that loop
across ordinary records and metrics. Existing automatic service/resource presets,
trace/log tails, exact facets and captured-record review are delivered foundations,
not missing categories. 375 addresses a demonstrated narrow-row interaction gap;
its actual result remains pending here, not assumed compact from markup.

373 teaches that useful grammar needs contextual discovery, not just copyable IDs.
374 teaches the stronger boundary: retained numeric data is not enough when source
presence/zero-threshold facts or mathematical geometry are lost. A new chart must
not hide that loss with rounding or an explicit-bucket alias. Future exponential
support needs another closed source/representation review, not another UI option.

## Revised candidate finite sequence

Architecture identified stronger source-confirmed gaps than another template family
or compatibility work already closed in 373. Prefer the following sequence after
375 acceptance; these remain conditional proposals, not implemented features.

### 376 — breadth: make unsupported exponential observations discoverable

374's actual 13 exponential points exist in source, but native discovery loops over
gauge/counter/explicit-histogram families only. Users asking what telemetry exists
should see those instruments with exact name/unit/identity and an explicit
unsupported/source-fidelity explanation, rather than infer that nothing was emitted.

Use existing instrument discovery rows and capability/refusal presentation. No
Preview/Run action or explicit-histogram alias is offered for this shape. Say that
zero-threshold/statistic presence and representation semantics are not retained
sufficiently for execution; a discovery row is not a conformance badge. Genuine
acceptance lists the pinned source's exponential instrument, preserves actual
identity/count meaning, and proves no execution or fabricated distribution. Stop
at honest metadata visibility, not a new evaluator or representation.

### 377 — depth: actual explicit-histogram exemplar evidence

An investigator selecting a histogram interval naturally wants a representative
reported trace. Existing native interval context deliberately matches resource/time;
it is not an exemplar. The pinned exporter advertises exemplar support, but Goo's
source/kernel does not retain or act on it. Begin a strict source-readiness gate
for one explicit-histogram exemplar fixture: trace/span IDs, event time, observed
value, filtered attributes and exact source identity must survive ingestion.

If those facts are retained and admitted, offer one explicitly named reported-
exemplar continuation through existing trace/record navigation, with its own fresh
read and immutable origin if captured. A reported reference is not proof the trace
still exists, is complete or uniquely caused the bucket. Invalid/unreported IDs,
out-of-scope time and missing trace evidence remain explicit. If source fidelity
or custody cannot close, publish a precise defer and advance the next cut. No
statistical contributor inference, metric-to-span join engine or automatic sampling.

### 378 — consolidate: native measurement refusal and recovery

The native Measurements request path flattens server failures into generic Error,
while other read owners already show structured source reasons and explicit fixed-
question recovery. Use the same concise SourceRefusal presentation and current-owner
rules for this main native surface. Keep scope/question unchanged through refusal;
explicit Run/Retry reads that exact frozen question, not a fresh lookback.

Distinguish source budget/protocol/unavailable from invalid configuration, no data
and cancellation. Preserve drafts, keep useful existing evidence/clock meaning
truthful, and retire late/hidden retries. No automatic read, duplicate nested retry
or new error catalogue. Genuine acceptance covers typed failure details, exact-
question retry, cancellation/late response and source-free navigation with current
focus on desktop/narrow. This is a cross-surface recovery connection, not a new
backend or project-wide transport rewrite.

## Product risks and reconciliation

This sequence serves the live-first loop: discover what was emitted, follow actual
reported evidence, recover a failed native investigation without losing scope.
Existing rows, inspectors, trace navigation and refusal components remain cohesive.
Exponential discovery must never be mistaken for evaluation support. Exemplar work
is a gate until actual raw identity/time/custody proves otherwise. Recovery must
not turn an old failed read into a moving rolling question.

Drop redundant native compatibility consolidation: 373 already closed its concrete
cross-layer drift bank. Messaging reusable views, broker backlog and review-task
lookup remain separate future candidates, not parallel queues. Do not reopen 374's
mathematical representation or schedule a broader platform/model. Root/planner
adoption awaits final 375 acceptance; no fourth maintenance extension is implied.
