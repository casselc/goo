## Essence and what actually changed

The core remains **live logs/spans → scope → isolate populations → drill or compare
→ preserve/reuse**. Ordinary OTel needs no manifest. The interface should expose
a next useful gesture beside evidence, with fixed UTC scope, state and data ahead
of configuration. Save a definition, Keep an occurrence and capture a fresh read
are different intents; concise action labels should carry that distinction.

394 removes a real distribution-to-customization detour without a second editor.
395 makes grouped count timelines participate in the shared grammar: small
multiples, Table and Heatmap share supplied identities, zero/unknown semantics
and destination configuration reuse. This is meaningful progress toward a
composable product, not a reason to launch arbitrary executable kinds or a
WYSIWYG platform next. Continue finite admissions where an existing dataset and
renderer can share one honest contract.

396 addresses a different dimension: a held parent's visible local edits must
match what Save preserves, while retired source actions remain retired. The source
now propagates valid grouped display changes while retaining separate source
staging state and explicit invalid Find feedback. Actual parent-return acceptance
must close before calling that reliable. Do not generalize a callback fix into a
universal lifecycle framework.

Live selection/Keep **already exists**, including server-attested membership in
`ui/tail.mjs`, and compact Activity mounts it. My earlier proposal of missing live
retention relied on stale documentation and was incorrect; do not create a second
retention implementation. Comparisons, trace waterfalls, triage, service/resource
dashboards, captured review/export, log-pattern reuse and native client duration
also already ship. Their names must not reappear as missing categories.

## Ranked finite user tasks

### 1. Breadth: follow a gauge observation from Services or Saved

**Task:** “This reported resource value looks interesting; inspect nearby logs or
spans and return to exactly the evidence I was viewing.”

This is a documented actual coverage gap: ordinary Measurements gauge context is
delivered, while service-expanded and saved gauges remain deferred. It extends a
proven natural gesture across important product surfaces rather than creating
another dashboard or data store. Services supplies live discovery; Saved supplies
frozen evidence, so the two parents must retain their different clocks/citations.

Use the existing timestamp-centered, clipped ±60s record question and explicit
Run, with exact environment/namespace/resource policies. Keep held Back source-free.
Do not infer metric-label predicates, causal contribution, full telemetry coverage
or saved custody for the fresh child. Start with existing admitted gauge snapshots;
stock/resource families and broader automatic joins stay outside this cut.

Acceptance: actual service and saved parents, known zero and unknown/stale points,
exact staged questions, explicit read, repeated held return and no new source read
for local selection. The frozen receipt must remain attached to the origin rather
than relabeling fresh records as captured evidence.

### 2. Depth: reuse grouped mean-duration views with explicit support

**Task:** “Which route or service group became slower during this interval? Reuse
that duration-over-time view on another compatible span population.”

Grouped duration execution already exists in `ui/grouped-time-series.mjs`; 395's
shared declaration arm is deliberately count-only. The missing part is checked
shared grammar/reuse, not another duration query or chart engine. Start with one
well-supported measure such as raw-cell mean duration, carrying exact contributing
count/sum and unavailable support. A source-feasibility review must establish those
fields before admission. If it cannot, retain count-only rather than invent support.

Use one qualified grouping and current fixed intervals/limits. Counts remain
counts; duration is visibly a duration with appropriate units and a shared duration
scale. Empty cells have no duration, not zero latency. Find/order cannot change
the scale population. No averaged scalar percentiles, fleet inference, stacked
latency totals or numeric arbitrary-transform platform. Percentiles require their
own raw-cell support and can remain outside this first arm.

Acceptance: independent raw duration/count oracles, empty/unknown/changed reads,
exact destination predicates/windows and no-read local switches/save/Inspect/Apply.
A count view and duration view must be human-comparable without silently sharing
an incompatible axis or denominator.

### 3. Consolidation: make wide data tables navigable on narrow screens

**Task:** “Read a bucket's bounds and observation count, or a group's share, without
losing which row and field I am looking at.”

Actual 392 narrow bucket Table places counts beyond the initial viewport; 394
ordinary Table similarly places shares offscreen. Final 395 Heatmap is improved:
shared UTC date, compact headings, readable literal group column and two visible
intervals on narrow screens. It still requires horizontal movement for more
intervals. Horizontal scrolling is valid; its discoverability and retained row
context should be a shared component concern, not a local rewrite per chart.

Audit only these concrete shared `goo-table` embeddings. Prefer a visible overflow
affordance, meaningful accessible region label and preserved group/header context;
consider priority or stacked layouts for ordinary three-column numeric tables where
that improves reading. Heatmaps should retain their matrix, not become cards.
Avoid sticky layout changes unless nested screenshots and keyboard focus prove
there is no clipping/obscuring. Preserve exact UTC/bounds, units, unknown states,
selection targets and caller-owned data. No new table framework or control panel.

Acceptance: standalone and nested server/SPA composition, keyboard horizontal
access, long/Unicode/missing/empty labels, zoom/narrow layout, focus visibility and
zero API reads. Before/after frames must show a concrete reading improvement.

## Simplification and reconciliation

- Keep one folded Investigate menu and contextual next actions; do not add a new
  home dashboard or permanently expand all analysis controls above the stream.
- Keep configuration-only controls distinct from source-read actions. 396's outcome
  should define the bounded regression contract, not restart repeated micro-fixes.
- Use component-owned styles, ordinary HTML labels/buttons/disclosures and exact
  accessible cell labels. 395's inherited uppercase row headers and default figure
  margins were real bugs; scoped fixes closed them. This supports checking actual
  parents, not a broad stylesheet rewrite.
- Further reusable-template profiles may be useful, but choose a demonstrable task
  and existing source contract before admitting another arm. Arbitrary user code,
  general WYSIWYG, multiplayer, alert delivery, bitemporal storage and warehouse
  execution remain separate product decisions.
- Annotation task choice remains deferred; existing annotation/review/export is not
  missing. Do not prioritize evidence infrastructure merely because it is easy to
  enumerate: the user explicitly prefers useful feature development over evidence
  accumulation for its own sake.

The planner should reconcile these three proposals with independent architecture
and frontend findings after 396 acceptance. They are ranked inputs, not three
simultaneously authorized implementations or a second permanent backlog.
