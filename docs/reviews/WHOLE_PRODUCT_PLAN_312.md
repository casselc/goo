## Product judgment

Retain the core: observe now, isolate a population, follow its supporting signals,
and preserve/reuse the result. The current Activity entry is data-first, ordinary
OTel data does not need a Goo manifest, and recent work has connected raw records,
authored charts, comparisons, portable questions and contributed controls. These
are useful delivered capabilities, not reasons to build another Home screen,
widget gallery, query engine or editor.

The strongest remaining problems are at transitions between valid pieces. A
selection command can outlive its context; an offered promotion can produce an
illegal composition; a return can retain obsolete lookup resources; a page can
claim a terminal state inconsistent with its count; a returned question can alias
caller state after its basis was frozen. Correct these concrete defects first.
Then make one active canvas and its true field/scope obvious before expanding more
service families or control kinds.

## Selected sequence and limits

The root selected a bounded **312 correctness bundle**: command leases/readiness,
explicit facet promotion, facet lookup disposal, terminal page diagnosis and returned
question detachment. UI and Go changes can proceed in parallel with independent
review. Their acceptance must include the relevant old-counterexample refusal and
current positive flow, not only implementation-shaped tests.

**313** then gives the investigation one active canvas with effective field/title
context and clear owner-appropriate return. Source owners remain separate even
when their duplicate scaffolding is hidden. A direct Activity-service shortcut
needs an explicit identity/environment/window and cross-signal predicate contract;
it is not permission to copy or silently discard a log filter in a span view.

**314** establishes physical source-cost budgets, then tests one equivalent leaner
acquisition path if the measured result justifies it. It must not cast an existing
partial DTO into a fictitious full snapshot, remove requested projections, infer
upstream coverage or deduplicate independent observations merely because the
queries look alike. Validation parity travels with the changed boundary instead
of becoming another unbounded schema/compiler programme.

Production readiness, a general visual editor and competitor-suite parity are not
certified by this review. Keep one finite current roadmap and retained/deferred
workstreams with trigger conditions. Reassess after these outcomes or sooner if a
more serious actual task failure changes the order.
