# 253 — retained record scope ownership

This is an executable internal-owner integration, not a new selector-entry UI.
Find environments and selector-capture Saved mounting remain gated.

1. Mount the production fixed-question owner in an isolated Go runtime using the
   existing ClickHouse source. Stage missing, empty and effective named scope.
   Staging sends no exploration request and shows the explicit policy/scope.
2. Edit a message filter. Run explicitly: the request retains the original exact
   window and selector. Named-only package/deployment controls remain disabled.
3. Change signal and request a fresh window. Run explicitly: the selected scope
   remains unchanged. Reject ambiguous incoming scope before changing the visit.
4. Pin a captured breakdown baseline. Explicitly edit the environment name. The
   baseline clears, and the next request uses the new legacy named scope without
   the prior selector. Pinning can calculate a supplied-cohort comparison; that
   is distinct from a telemetry read.
5. Dispose the owner and remove its temporary runtime/store. No lab capture or
   existing stored data is changed.
