# Read later table fields without losing context

The executable [402 journey](402-table-context.spec.js) exercises three existing
product surfaces over real OTel data. Execution results belong in VALIDATION.md;
the standalone component fixture is synthetic layout coverage, not source evidence.

1. Run an ordinary numeric log question and choose **Table** in Chart settings.
   Read the later quantitative fields, units and support while the group stays
   visible at the leading edge. The cue appears only while content lies beyond
   that edge. The query and supplied population remain unchanged.
2. Run a grouped mean-duration question and choose **Table** for its timeline.
   Scroll through UTC intervals and exact duration/support fields without losing
   the group. Literal names, interval bounds, zero and unavailable values retain
   their meaning. Keyboard arrows and horizontal pointer wheel work in the same
   native table region.
3. Open a Saved gauge and choose **Table** in the retained stream. Read the value,
   state and reason beside the retained observation timestamp. The original
   receipt, read window and custody time remain the same; scrolling reads nothing.
4. At 390px, each table stays inside its panel. The leading identity occupies a
   bounded portion of the viewport, leaving later fields usable. Returning to the
   beginning clears the leading-edge cue; a table that fits receives no cue.
5. Standalone SSR markup and a table moved into a nested/detached host retain the
   same native cells and focusable region. Resize, disclosure and reconnect update
   overflow locally. In a vertically constrained viewport, headers stay visible.

The journey asserts source/store/SQL counters do not change during these gestures,
exact cell text and tooltips stay unchanged, and chart datasets/display definitions
are unchanged. It does not claim a performance improvement or completeness from
layout behavior. Screenshots are generated by the running app after acceptance.
