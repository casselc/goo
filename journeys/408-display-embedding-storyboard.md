# 408 · Embed supplied displays

A developer embeds Goo's shared display elements without adopting its application
runtime or query client. These reference datasets are explicitly synthetic;
this journey establishes embedding behavior, not source telemetry coverage.

1. Open `/display-examples` with the display import held. The HTML summary still
   reads “20 captured records.” The ranked chart already has snapshot/display
   properties assigned before custom-element registration.
2. Release the public `display.mjs` import. The summary upgrades its JSON
   attributes; a detached chart receives the same supplied summary through
   properties. Independent imports receive distinct local identities with no
   completeness proof; all other supplied facts stay intact. The ranked chart
   adopts its early properties. No application
   namespace, source request or browser storage access is needed.
3. Use the keyboard to select the supplied `api` group. The host handles the
   selection intent locally. Switch Bars/Table through a native select; the full
   supplied facts, accepted local identity, exact counts, unknown coverage and
   sampling stay intact.
4. Assign properties to a detached element, mutate the caller's original objects,
   then append, remove/update and reattach it. The component keeps isolated values.
   Updating an HTML attribute also refreshes its display without changing data.
5. Request a complete-only plot from these imported, uncertain fixtures. The
   display refuses it; authored metadata does not become a completeness proof.
   Inspect the compact reference at desktop and 390 px.

Executable check: `408-display-embedding.spec.js`. It rejects source APIs,
application modules, network clients and storage effects, and records an explicit
synthetic-fixture report in `artifacts/display408/summary.json`.
