# Contextual Activity facet verification

Thirty-two deterministic Hegel cases call the actual counted-value projection,
result adapter and Activity entry helper through a JavaScript bridge. Generated
logs/spans vary qualified field namespaces, effective/current-only environment
policy, complete predicate trees, exact latest and older observation windows,
missing/present-empty/literal values, and counts beyond 2^53. Exact field/scope
identity and full count conservation come from independently generated Go inputs.
Corrupt source scope, partitions, receipts and unsupported numeric columns must
refuse. A controlled transport proves a late result cannot restore a changed
scope. Fetch is denied during the pure projection/entry checks.

The native Quint model separates local inspection, field entry and predicate
staging from explicit counted-value reads (one source acquisition, two SQL reads).
It also rejects completion after scope retirement. The actual continuous browser
ledger validates the observed budgets; a separate actor runs afterward. These
finite checks do not prove exhaustive concurrency or source completeness.

Root runs heavy checks serially, from `verification/`, with current Go and local
Node/Quint on PATH:

```
GOO_FACETS421_REPORT=/workspace/goo/artifacts/activity-facet-entry421/report.json \
  go test ./facets421 -count=1 -v
```

Native Quint is mandatory. The actual-ledger test skips only in arithmetic-only
local runs without a report; milestone acceptance requires the completed real-
source report and no skips. Generated-only preflight uses `-run '^TestGenerated'`.
Raw browser recordings remain ignored; docs retain actual review frames.
